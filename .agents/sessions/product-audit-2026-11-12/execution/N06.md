# N06 receipt: command execution defaults and job lifetime

**Status:** implemented (one scope item is partial: the user-cap policy exists as an SDK option but no config file feeds it yet; see "Not done").

Findings: exec-jobs-01, exec-jobs-09, exec-jobs-18. Built on the uncommitted B19–B21 work in the same files; no B19–B21 change was reverted.

## Changed files
- `sdk/src/tools/run-terminal-command.ts`:
  - New `DEFAULT_SYNC_TIMEOUT_SECONDS` (120), `IDLE_OUTPUT_HINT_MS` (30 000), the `TerminalTimeoutPolicy` type and `resolveTerminalTimeout()` (lines ~48-108).
  - `timeout_seconds` is now optional. Explicit values keep their meaning, approval waits included. An omitted SYNC timeout becomes a 120 s execution-time timer, armed at dispatch, so approval waits do not count. The timer stops the owned scope with SIGTERM, a grace period, then SIGKILL. A finite parent deadline still applies through the derived context. The host-only `timeoutPolicy` can cap or forbid `-1`.
  - New params `idleOutputHintMs` and `onIdleOutput`.
  - SYNC stdio is now `ignore-pipe-pipe` / `['ignore','pipe','pipe']`, plus `stdin.end()` for backends that still hand over a pipe.
  - Idle-output watchdog: it fires one hint callback per silent period and adds `idleOutputMs`/`idleOutputHint` to the result. It never kills the command.
  - Cancellation keeps partial output. In the close-path abort branch and the error-path cancelled branch, it returns bounded stdout/stderr and finishes the spool artifact instead of discarding it.
  - The default-timeout error message tells the model to raise `timeout_seconds`.
  - BACKGROUND jobs pass `attached: !detach` to `startBackgroundJob`.
- `sdk/src/tools/attached-job-lifetime.ts` (new): the attached-job registry and process hooks.
  - It unrefs the job child and its stdio, so a natural end is possible.
  - On `beforeExit` and on SIGINT/SIGTERM/SIGHUP it runs the cooperative B20 stop (`scope.requestStop('owner-shutdown')`), bounded at 3 s.
  - After that stop it exits with 128 + the signal number, but only when no other listener owns the signal. When another listener exists (the CLI renderer cleanup), the host keeps control of exit.
  - The synchronous `exit` hook sends SIGTERM to each live group, waits up to 300 ms, then sends SIGKILL.
  - Hooks are installed only while an attached job is live.
- `sdk/src/tools/background-jobs.ts`: new `attached?: boolean` param. Attached jobs are registered with a stop function that follows the `kill_job` scope path with the `owner-shutdown` reason (status `stopping`, then `finalizeCleanup`). Transferred jobs are not registered.
- `sdk/src/run.ts` (one line, ~3450): removed `timeout_seconds ?? -1`, so an omitted value reaches the SDK default.
- `common/src/tools/params/tool/run-terminal-command.ts`:
  - `timeout_seconds` drops `.default(-1)` and gets new description text.
  - New `idleOutputMs`/`idleOutputHint` result fields.
  - The tool description's "Do:" notes now cover closed stdin, the idle hint, the 120 s default and partial output on timeout or cancel.
- `agents/basher.ts`: an omitted `timeout_seconds` is passed through as omitted, so the SDK default applies (120 s for SYNC, unbounded for BACKGROUND). Parameter description updated.
- `agents/__tests__/basher.test.ts`: four expectations updated from `timeout_seconds: -1` to omitted.
- `agents/types/tools.ts`, `.agents/types/tools.ts`, `common/src/templates/initial-agents-dir/types/tools.ts`: the `timeout_seconds` doc line was edited by hand to match the schema text.
- `cli/src/data/initial-agent-type-sources.generated.ts`: regenerated with `cli/scripts/generate-init-type-sources.ts`. The only diff is that doc line.
- `sdk/src/__tests__/run-terminal-command.test.ts` line 53: `params.timeout_seconds ?? -1`, needed because the param is now optional.
- `sdk/src/__tests__/attached-job-exit.test.ts` (new) and `sdk/src/__tests__/fixtures/attached-job-exit-child.ts` (new): real-process ports of probes p1 and p2.
- `sdk/src/__tests__/terminal-sync-defaults.test.ts` (new): real-child SYNC defaults tests.
- `sdk/README.md`: new paragraph after the `runTerminalCommand` example covering stdin, the default timeout, `timeoutPolicy`, the idle hint, partial output and attached/transferred job lifetime.

## Not done / follow-ups
- **User/host cap from config:** `timeoutPolicy` (`defaultSyncSeconds`, `maxSeconds`, `allowUnbounded`) is a trusted SDK option on `runTerminalCommand`. Nothing reads it from `openbuff.json` yet, and `run.ts` does not pass it. The default policy allows an explicit `-1`. Wiring a `terminal.maxTimeoutSeconds` / `allowUnboundedTimeout` setting belongs in `sdk/src/host-config.ts`, which N02 owns, plus a one-line pass-through in `run.ts`.
- **Idle-hint event:** the hint is a result field plus an `onIdleOutput` callback. `run.ts` does not yet forward the callback to the CLI as a live event.
- **Explicit timeouts:** these still include approval waits, as documented. Only the omitted-timeout default excludes them.
- **Transferred jobs:** these still hold the event loop open, so an SDK script whose only remaining handle is a transferred job does not end naturally. This is existing "as designed" behaviour; the test uses `process.exit`. Their stdout/stderr pipes also break when the host exits, so a chatty transferred job may get SIGPIPE. Not addressed.
- **CLI exit summary:** the finding suggests printing surviving detached jobs in the CLI exit summary. Not done.
- **Windows:** the exit hook falls back to `child.kill` because there are no process groups. Untested.
