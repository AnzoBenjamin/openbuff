**Status:** partial. The request-side fix (markers on the wire for Anthropic and OpenRouter→Anthropic, none for strict OpenAI-compatible routes) and its wire tests are done. ## Changed files
- `sdk/src/impl/llm.ts`
  - Streaming path (`:1464`): `includeCacheControl` is now `compatibility.stripCacheControl === false`, the same gate as the non-streaming paths. It replaces `isChatGptOAuth && …`.
  - New `withToolsCacheBreakpoint` (`:1132`), applied at `:1486`: when markers are on, the last tool gets an `anthropic.cacheControl` breakpoint. That is the 4th of Anthropic's 4 allowed breakpoints, and it keeps the tool block cached when the system prompt changes.
- `sdk/src/provider-config.ts`
  - New `isOpenRouterAnthropicRoute` (`:2572`). `resolveConfiguredProviderModelMetadata` (`:2556`) sets `stripCacheControl: false` for `anthropic/*` models on an `openrouter.ai` host.
  - Other OpenRouter models and other hosts keep the strict default. The edit is in the route-resolution compatibility block only. The loader and merge code is untouched.
- `packages/internal/src/openai-compatible/chat/convert-to-openai-compatible-chat-messages.ts`, `openai-compatible-api-types.ts`
  - A system message that carries `cache_control` is now sent as one text part holding the marker. OpenRouter only honours markers on content parts. Other metadata stays on the message.
  - This is outside the ownership list. The edit is small and has a test (below).
- `docs/local-mode.md`: the `stripCacheControl` line now states the defaults and the OpenRouter `anthropic/*` rule.
- Tests:
  - `sdk/src/__tests__/llm-cache-control-wire.test.ts` *(new)*.
  - `sdk/src/__tests__/fixtures/fake-llm-server.ts` *(new; shared with N07)*. It is a fake Anthropic and OpenAI SSE server with a prompt-cache simulation and a real host-config snapshot helper.

  - A system-message case in `packages/internal/.../convert-to-openai-compatible-chat-messages.test.ts`.
