# N10: Eval regression gate

**Status:** partial. Everything except a live run is implemented. No live LLM eval was run (no keys), so "a deliberately broken prompt change fails the PR subset" is shown through the gate logic, the offline pipeline and the key-free dry run, not through a live CI run.

## Changed files
- `evals/buffbench/main-nightly.ts` (rewritten): the gated entry for `--subset nightly` (base2 on `eval-codebuff.json`) and `--subset pr` (`autodetect-knowledge`, `update-tool-gen`, `fix-agent-steps`).
  - The default agent is `base2`; it was `base2-free`, which does not exist.
  - Flags: `--tasks`, `--agent`, `--results-out` (copies FINAL_RESULTS.json there for the artifact) and `--dry-run` (validates the eval file, task ids and agent, and prints static prompt tokens with no LLM call).
  - It exits 1 when no run is measured; the old version always exited 0.
  - DI seam: `runNightly(options, deps)`.
- `evals/buffbench/regression-gate.ts` (new): CLI and library.
  - It reads current and baseline FINAL_RESULTS.json (a file or an artifact directory) and calls `compareRuns`.
  - It exits 1 past the noise band, 2 on bad input, and 0 when there is no baseline yet. An empty run still fails.
  - `DEFAULT_NOISE_BAND`: score -0.5, errored runs +1, edit-commit rate -10 pts, tool error rate +10 pts, static prompt tokens +10%. Each value can be set by a flag.
  - It also fails an agent that is missing or has no measured runs.
  - The markdown report goes to `--report` and to the step summary.
- `evals/buffbench/compare-runs.ts`: `compareRuns(before, after, { scoreNoise, errorNoise })`. The defaults keep the old strict 0.01 / 0 behaviour.
- `evals/buffbench/quality-metrics.ts` (new): per-run counts from the trace, including subagents: tool calls/results/errors, edit results/committed, LSP calls. Pooled per-agent rates are edit-commit rate, tool error rate and LSP call rate. Also a markdown table.
- `evals/buffbench/static-prompt-tokens.ts` (new): offline count of system + instructions + step prompts plus provider-facing tool definitions. base2 today: 35,502 tokens, of which 13,564 are prompt and 21,938 are 42 tools.
- `evals/buffbench/run-buffbench.ts`: each `EvalRun` gets `qualityMetrics`. Each agent gets `qualityMetrics` with `model` (the definition model, otherwise the provider route) and `staticPromptTokens`. A "Harness quality (per model)" table is printed.
- `evals/buffbench/types.ts`: optional `EvalRun.qualityMetrics` and `AgentEvalResults.qualityMetrics`. This file already had other workers' uncommitted B-task edits; mine are two additive optional fields.
