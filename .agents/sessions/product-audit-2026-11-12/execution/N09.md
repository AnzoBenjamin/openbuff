# N09: Ship tree-sitter queries in release builds

**Status:** implemented. A real release binary was not rebuilt (see Not done). The installed smoke was verified with a compiled probe binary run from a tarball built with the workflow's own file list.

## Changed files
- `cli/scripts/release-tarball-files.sh` (new): the one tarball file list for every release tar step. It lists the binary, `tree-sitter*.wasm`, `tree-sitter-manifest.json` and every `tree-sitter-queries/*.scm`, plus `libopentui.dylib` and `rg` with `--legacy-macos`. It exits 1 when any of them is missing.
- `.github/workflows/cli-release-build.yml`: both "Create tarball" steps (matrix and win32) use the shared list and assert that the tarball's `.scm` count equals `packages/code-map/src/tree-sitter-queries/*.scm`. The tarball is now created before the smoke steps. All three smoke steps (native, win32, emulated arm64) extract the tarball and run from it, so they test the installed layout. Before this, they copied wasm files out of `cli/bin`. The arm64 step also runs `--smoke-code-map`.
- `cli/scripts/build-binary.ts`: hashes each copied query into a new manifest key, `queries: {name: sha256}`. Older wrappers read only `files`, so they are unaffected. The build fails if no query was copied.
- `cli/release/index.js` and `cli/release-staging/index.js` (the npm wrappers):
  - `getManagedSiblingNames` now installs `tree-sitter-queries/<name>-tags.scm` next to the binary. A symlinked or non-directory `tree-sitter-queries` entry is rejected.
  - The target directory is created before commit.
  - `getTreeSitterAssetProblems` checks the manifest's `queries` hashes when that key is present (missing or checksum problems trigger the existing repair path). Manifests without the key are accepted, so old installs never loop on re-download.
- `packages/code-map/src/languages.ts`: query candidate paths are factored into `getQueryCandidatePaths`, with the same order as before. New `TAG_QUERY_FILES` and `getTagQueryStatus({ exists? })` report available and missing queries from the paths the loader reads.
- `packages/indexer/src/index.ts`: re-exports `getTagQueryStatus`, `getFileTokenScores` and `TagQueryStatus`, so the CLI needs no new dependency.
- `cli/src/commands/index-command.ts`:
  - New `applyTagQueryStatus` and a `getTagQueryStatus` DI seam.
  - `/index status` and `/index rebuild` (both the string and block renderers) switch the state to `degraded`. They add the line `degraded: no queries — N of 14 tree-sitter tag queries missing (…)` above the manager's message.
- `cli/src/utils/code-map-smoke.ts` (new): `runCodeMapSmoke` and `formatCodeMapSmoke`. They index a two-file TS fixture and require non-empty symbols, calls and imports, with every query present.
- `cli/src/index.tsx`: a 14-line `--smoke-code-map` handler next to `--smoke-opentui`. **This file is owned by N02 (trust)**, and the edit is a small targeted addition.
- `cli/scripts/smoke-binary.ts`: requires the `--smoke-code-map` probe (marker `code-map smoke ok`) after the tree-sitter probe.
- `cli/knowledge.md`: one refresh entry, for the pre-push drift guard.
- Tests (new or extended):
  - `packages/code-map/__tests__/tag-query-status.test.ts`
  - `cli/src/commands/__tests__/index-command.test.ts` (new N09 describe block)
  - `cli/src/__tests__/release-wrapper.test.ts` (new N09 describe block)
  - `cli/src/utils/__tests__/code-map-smoke.test.ts`
  - `scripts/__tests__/release-eval-workflows.test.ts` (release section)

The npm wrapper `files` list needs no change. The wrapper ships only JS and downloads the release tarball; the queries reach users through the tarball and `getManagedSiblingNames`.

## Acceptance
- **The tarball built by the release workflow's file list contains every query file: met.** `/tmp/n09/verify-tarball.sh` (log in `/tmp/n09/verify.log`) runs `release-tarball-files.sh cli/bin openbuff`, tars into `/tmp/n09/openbuff-linux-x64.tar.gz` and gets 32 entries. 14 of them are `.scm`, and the `.scm` list diffs clean against the source directory. Before the fix this tarball had 18 entries and 0 `.scm`. Guarded by `scripts/__tests__/release-eval-workflows.test.ts`: both tar steps use the script and the count check, and the script refuses a bin dir without queries.
- **The installed smoke test indexes a TS fixture and finds symbols, calls and imports: met, with a probe binary.** `bun build --compile` of `cli/src/utils/code-map-smoke.ts` plus the tree-sitter pre-init went to `/tmp/n09/probe-bin`. It was packaged with the same list, extracted to `/tmp/n09/install` and run from `/`. Output: `code-map smoke ok (symbols=3 calls=1 imports=1 queries=14/14)`, exit 0. `cli/src/utils/__tests__/code-map-smoke.test.ts` covers the same logic in-process.
- **With the queries removed, `/index status` says degraded: met.**
  - With `tree-sitter-queries/` removed from the install, the probe prints `code-map smoke FAIL (symbols=0 calls=0 imports=0 queries=0/14)` and exits 1.
  - `/index status` and `/index rebuild` with missing queries show `Index status: degraded.` and `degraded: no queries — …` (index-command tests "says degraded when the tag queries are missing" and "block renderer and rebuild path report the same degradation").
  - `getTagQueryStatus({ exists: () => false })` reports all 14 missing (tag-query-status test).
