# N02: Project trust gate for executable and credential-bearing config

**Status:** partial. SDK enforcement, persistence, the CLI flag path, a pre-render terminal trust prompt and the headless notice are implemented and tested. The trust screen is a plain-terminal `[y/N]` prompt shown before the OpenTUI renderer mounts. It is not yet an OpenTUI component, and there is no `/trust` command (see Not done).

## Design

I reused the existing mechanisms and did not build a parallel one:
- **Decision input.** The SDK decision is a new optional field `HostConfigurationInputs.trust.projectConfig` (`'trusted' | 'untrusted'`). It sits next to `ancestorConfig` and `projectReadableRoots`, is captured by `captureAmbientHostInputs`, and is validated and hashed into `sourceBytesIdentity` like the other trust fields.
- **Gate location.** The gate lives in both provider-config loaders, at the same per-fragment point where the M1-T3 `apiKeyEnv` origin filter already runs. The captured `loadProviderConfigForHost` is used by `run()`, `serve` and the SDK. The legacy `loadProviderConfigSync` is used by the CLI and the hot path. Both loaders now fold through one shared `mergeScopedFragments`.
- **Scope.** A fragment is user scope if it comes from the user config dir or the explicit `OPENBUFF_PROVIDER_CONFIG` selection. Everything else (project and ancestor `openbuff.json` / `openbuff.d/`) is project scope.
- **One decision.** On the CLI, one decision drives the existing `effectiveTrust`, which already gated `.agents/**`, project skills and `.agents/mcp.json`. `--trust-project-agents` and the serve `trusted-roots.json` allowlist feed the same decision.

Untrusted project scope can only tighten policy:
- **Providers.** These are withheld:
  - any provider with `apiKeyEnv`;
  - any `chatgpt-oauth` provider;
  - any project redefinition of a provider id the user already has (this covers `baseURL` overrides).

  Keyless new providers still load.
- **Routes.** A project-set route is reverted unless it resolves to a provider the user configured. This covers `defaultModel`, `visionModel`, `modes.*`, `agents.*`, `failoverModels` entries and `indexing.semantic.model`. Attribution in `sourceFiles.routes` follows the value that took effect.
- **Hooks.** `fileChangeHooks` and `autoFileChangeHooks: true` are withheld.
- **Approval mode.** `approvalMode` is applied only if it is at least as strict as the current value. The order is allow-all < balanced < strict.
- **Sandbox.** A project `sandbox` block that would turn a user `sandbox.mode: "project"` back to unrestricted is withheld.
- **Semantic indexing.** `indexing.semantic.enabled: true` is withheld unless the user already enabled it.
- **Already gated.** `execution`, `readableRoots` and `sandbox.allowPaths` keep their existing gates. Those are user-dir or explicit-file origin for `execution`, and `OPENBUFF_TRUST_PROJECT_READABLE_ROOTS` for the other two. Project trust does not widen them.
- **Skills and agents.** Project skills are kept out of `fileContext.skills`, and the `skill` tool's disk fallback skips project dirs. `.agents/` agents were already excluded by the CLI flag, and the SDK loads home agents only.

**What each item records.** Every withheld item is recorded in `LoadedProviderConfig.projectTrust.gated` as `{kind, filePath, summary}`, where `filePath` is the file that declared it. The list sits beside `diagnostics`, not inside it, because `getOpenbuffProviderReadiness` treats any diagnostic as fatal.

**Persistence.** Decisions are stored in `<configDir>/project-trust.json`, written atomically with mode 0600. Each record is `{decision, configHash, decidedAt, source}`, keyed by the project's realpath. `configHash` is a sha256 over the project-scope config files plus `<root>/.agents/mcp.json`. A hash mismatch gives `reason: 'changed'`, which means untrusted until asked again. A malformed store fails closed.

**Precedence.** From highest to lowest:
1. The SDK `run({ trustProjectConfig })` option, or `hostConfiguration.trust.projectConfig`.
2. The process override `setProjectTrustOverride({projectRoot, decision})`, which the CLI sets after its decision and which applies only to the matching realpath.
3. `OPENBUFF_TRUST_PROJECT_CONFIG=1`.
4. The stored decision.

## Acceptance
- **Probes ported as tests; untrusted shows no capture-server request, no key, no hook execution, `balanced` kept and no project skill in the prompt: met.** All cases are in `sdk/src/__tests__/project-trust-gate.test.ts`.
  - p1: `untrusted: balanced is kept on the SDK and CLI paths…`. Both the snapshot and the legacy loader return `balanced`, `createHostExecutionServices().approvalMode` is `balanced`, and `rm -rf`, force-push and curl exfil are each not allowed.
  - p2: `untrusted: no request reaches the attacker…`. A fetch recorder sees requests only to `api.anthropic.com` and none to the attacker origin. The `OPENAI` key is never sent, `defaultModel` and `agents.base2` are reverted, and every gated item names the project `openbuff.json`.
  - p2b: `untrusted: no hook is configured and nothing executes`. The real host services and `runFileChangeHooks` run and no marker file is created.
  - p3: `untrusted: no project skill in the session or the disk fallback`. The real `initialSessionState` and `handleSkill` are used.
- **After trust, the same fixtures behave as configured: met.** The `trusted: …` tests show `allow-all` applies, the request goes to the attacker origin with the key, the hook writes the marker, and project skills load and take precedence.
- **A config change after trust re-prompts: met.** Tests `a stored grant applies to both loaders, and a config change re-prompts` and `changing .agents/mcp.json also invalidates a stored grant`. The CLI side is covered by `a stored decision is not asked again; a changed config is`, and the tmux check below.
- **`--trust-project-agents` still works for CI and is recorded as an explicit grant: met.** CLI test `--trust-project-agents is recorded as an explicit grant` and SDK test `the CLI flag records an explicit grant that SDK runs then honour`. A live `openbuff run --trust-project-agents` wrote `{"decision":"trusted","source":"flag"}`.
- **First-launch trust screen listing exactly what the project config would enable: partially met.** The plain-terminal prompt before the renderer lists each gated item with its file, plus project agents, skills and mcp.json. It persists the answer and, from tmux, behaves as below. It is not an OpenTUI screen.
- **Warnings name the file that took effect: met.** Each gated item carries `filePath`, and the CLI prompt and notice print it. The ancestor warning is re-attributed (test `the ancestor warning no longer blames the user global config`).

## Not done / follow-ups
- **OpenTUI trust screen.** The prompt is plain readline before the renderer, and the typed answer is not echoed while it is read. Follow-up for B29: an in-TUI screen, a `/trust` command to review or revoke, and asking on project switch. Today a project switch honours stored decisions and the flag but never asks.
- **What the hash covers.** It covers project-scope config files and `.agents/mcp.json`, but not `.agents/*.ts` agents or skill files. Editing an agent does not re-prompt.
- **Legacy `trusted-roots.json`.** It is still honoured for `serve` as an explicit root grant, without a hash. No command writes it.
- **SDK default changed.** An SDK `run()` with no decision now leaves project skills out and gates project `openbuff.json`. Hosts must pass `trustProjectConfig: true` or rely on a stored grant. The CLI sets the process override after its decision, so in-process SDK runs follow it.
- **Out of scope.** `execution`, `readableRoots` and `sandbox.allowPaths` keep their separate existing gates, and project trust does not unlock them.
- **Edits in files owned by other tasks:**
  - `sdk/src/provider-config.ts`: loader/merge regions only, which N02 owns. I did not touch the preset or local-endpoint blocks.
  - `packages/agent-runtime/src/tools/handlers/tool/skill.ts`: a targeted fallback edit. No owner is listed.
  - `common/src/util/file.ts`: an optional field.
  - `sdk/src/__tests__/model-provider.test.ts` and `run-state-home-policy.test.ts`: assertions updated for the new rule.
