# N04 (remaining parts): typed results instead of silent empty or false success (receipt)

**Status:** implemented. This covers the non-web N04 items: read-search-01, read-search-12, language-intel-02, language-intel-07, exec-jobs-13, memory-context-05 and memory-context-06. The web parts are in `N04-web.md`. The 401/403 failover notice is in `N07.md`.

## Changed files

### read-search-01: memory-first short-circuit removed from exhaustive tools
- `packages/agent-runtime/src/orchestration/discovery-coordinator.ts`: `evaluateMemoryCover` takes a new `exhaustive?: boolean`. When it is true, the result is always `decision: 'full'` with reason `exhaustive-tool`. Covering excerpts are returned only as hints. The old logic now lives in `evaluateMemoryCoverInner`, unchanged, so `query_index` keeps its skip/narrow behaviour. A new export, `EXHAUSTIVE_DISCOVERY_TOOLS`, lists glob, list_directory, code_search and find_files_matching_content.
- `packages/agent-runtime/src/tools/handlers/tool/glob.ts`, `list-directory.ts`, `code-search.ts`: the skip outputs (`buildSkipOutput`) are deleted, and so is code_search's narrow-to-gaps rewrite. Memory now only feeds the `memoryReuse` accounting (always `full`, reason `exhaustive-tool`), and the real client call always runs. No memory hints are added to the tool output; see Not done.
- `packages/agent-runtime/src/tools/handlers/tool/find-files-matching-content.ts`: this is the quarantined sibling. It now passes `exhaustive: true` (a one-line change), so its skip branch cannot fire.

### read-search-12: missing-file errors suggest near-match paths
- `common/src/util/path-suggestions.ts` (new): `rankNearPaths` ranks paths by bounded Levenshtein distance on the basename. A candidate qualifies at no more than max(1, len/3) edits. Ties prefer the same directory, then the closer full path. At most 3 results.
- `common/src/tools/results/filesystem.ts`: `filesystemErrorSchema` gains an optional `candidates: string[]` (max 3).
- `sdk/src/tools/read-files.ts`: `getFilesStructured` attaches `error.candidates` to `not_found` items. It lists the nearest existing ancestor directory of the missing path, at most 3 hops up and 2 levels deep, capped at 2,000 entries, skipping node_modules, .git, dist and similar. Every candidate must pass `authorizeReadTarget`, so blocked and sensitive files (for example `.env`) are never suggested. This is best-effort: any failure yields no candidates. The error message and the `discover_path` recovery are unchanged.
- `packages/agent-runtime/src/tools/handlers/tool/read-outline.ts`: a missing file now also sets `errorMessage` (with "Did you mean: …") and `candidates` from `fileContext.fileTree`. The legacy `outline: 'Error: File does not exist.'` text is kept for the existing renderer and its tests.
- `common/src/tools/params/tool/read-outline.ts`: optional `candidates` added to the output schema.

### language-intel-02 and language-intel-07: LSP statuses
- `common/src/tools/params/tool/go-to-definition.ts`: new shared `lspUnavailableSchema` with `reason`, `languageId?`, `status?: 'unavailable' | 'not_installed'`, `nextStep?`, `command?` and `install?`. All 7 LSP tool schemas use it: go-to-definition, find-references, hover-type, workspace-symbol, rename-symbol, code-action and extract-symbol.
- `sdk/src/services/lsp-multiplexer.ts`:
  - New unavailable reasons `not-installed` and `workspace-symbol-unsupported`. `LspServerUnavailableError` gains `command` and `install`.
  - A spawn ENOENT, whether a child `error` event or a synchronous throw, rejects with `not-installed` instead of `crashed`.
  - The initialize-failure wrapper no longer re-wraps an `LspServerUnavailableError` as `protocol`.
  - A per-multiplexer negative cache (`missingCommands`) answers later calls immediately without respawning.
  - For workspace/symbol, a warm server that answers `null` now returns `[]`. A warm server that rejects the request throws `workspace-symbol-unsupported`. `null` now means only "no warm server".
- `sdk/src/services/lsp-install-hints.ts` (new): install hints keyed by server command. They live in the SDK rather than in `common/src/util/language-capabilities.ts`, because adding a field there changes the golden manifest in `language-capability-manifest.test.ts` (schemaVersion 1). I tried that first and reverted it.
- `sdk/src/services/language-intelligence.ts`:
  - `toUnavailable` adds `status`, a reason-specific `nextStep`, `command` and `install`.
  - `workspaceSymbol` maps a `null` multiplexer result to `unavailable: { reason: 'no-warm-server', status: 'unavailable', nextStep }`. The next step points to go_to_definition, hover_type or find_references to warm a server, or to code_search or query_index. Before this change it returned `symbols: []`.
- `cli/src/components/tools/language-intelligence.tsx`: a `not_installed` result renders "language server not installed (cmd) · install: …".

### exec-jobs-13: kill_job reports killed only after an observed exit
- `sdk/src/tools/kill-job.ts`:
  - After `killBackgroundJob`, it polls the job status every 25 ms until the status is terminal, for up to `KILL_JOB_EXIT_WAIT_MS = 3_000`. The budget can be injected through `waitForExitMs`.
  - `killed: true, exitObserved: true` with the exit code is returned only when the exit was seen.
  - Otherwise it returns `killed: false, exitObserved: false, status: 'stopping'`, with a `reason` and a `nextStep` (check_job, automatic SIGKILL escalation after 5 s, or kill_job with SIGKILL).
  - `background-jobs.ts`, which N06 owns, is not touched.
- `common/src/tools/params/tool/kill-job.ts`: optional `exitObserved`, `reason` and `nextStep` added to the output schema. The tool description is unchanged.

### memory-context-05: compaction labelled extractive
- `agents/context-pruner.ts`:

  - `spawnerPrompt` no longer says "summarizing". It now says the conversation is condensed extractively and that no LLM summary is written.
  - The "LLM-based" comment is fixed.
  - The model-visible `SUMMARY_HEADER` is unchanged.
- `packages/agent-runtime/src/util/context-pruning.ts`, `tool-result-eviction.ts`, and the `run-agent-step.ts` comment at about line 2838: comments no longer call the default pass an LLM or full-model-call pass.
- `cli/src/components/renderers/compaction-box.tsx`: a completed semantic pass is titled "Context compacted (extractive)".

### memory-context-06: pruner skips and failures shown in the compaction card
- `packages/agent-runtime/src/util/runtime-semantic-compaction.ts`: it now returns a `RuntimeSemanticCompactionOutcome`, which is `completed`, or `skipped`/`failed` with a `reason`.
  - Skipped cases: the pruner's own run; the agent does not list `context-pruner` in `spawnableAgents` (the reason names the agent and the fix); the pruner template cannot be loaded.
  - Failed cases: a thrown error, or an `executeSubagent` error output or `failed` termination. Before this change those were swallowed and treated as success.
- `common/src/types/print-mode.ts`: the `context_compaction_status` event gains optional `outcome: 'skipped' | 'failed'` and `reason`. Both are additive.
- `packages/agent-runtime/src/run-agent-step.ts` (owned by another worker; targeted edits):
  - New `compactionOutcomeFields` helper.
  - New `pendingCompactionOutcome`, reported by `settleCompactionStatus`.
  - The overflow-retry and empty-stream-retry passes include their outcome in their own `settled` events.
  - One comment changed.
- `cli/src/types/chat.ts` (pre-modified by another worker): optional `passOutcome` added to `CompactionContentBlock`.
- `cli/src/utils/sdk-event-handlers.ts` (pre-modified by another worker): `declinePendingCompactionBlocks` copies `passOutcome` and `reason` (capped at 400 characters) from a `settled` event onto the declined card.
- `cli/src/components/renderers/compaction-box.tsx`: a skipped pass is titled "Compaction skipped — context unchanged" and a failed pass "Compaction failed — context unchanged". Both use the warning tone and show the reason line.

## Not done and follow-ups
- **Memory hints:** no hints are added to glob, list_directory or code_search output. The scope allowed hints but did not require them, and the old outputs had no schema slot for them. `evaluateMemoryCover({ exhaustive: true })` still returns the covering excerpts if a later task wants a `memoryHints` field marked as memory-sourced.
- **query_index:** it still uses memory skip/narrow. read-search-01 suggests labelling it `provenance: 'memory'` and checking each served path against the query. That was not in N04's scope.
- **Generator-path pruner:** the generator-driven pruner path (`spawn_agent_inline` from handleSteps agents such as base2) does not yet report a skipped or failed outcome on the settle. Only the runtime-driven pass does.
- **Governor budget:** a skipped pass still consumes governor budget (`recordPassAnnounced` runs before the skip is known). memory-context-06 lists "do not consume budget on a skipped pass" as a further fix.
- **LSP gaps (language-intel-07):** the LSP tools are still advertised unconditionally. There is no `detect` probe, no `/lsp status` command and no docs page. Those belong to N11/B-series deferral. `workspace_symbol` still takes no `path`/`language` parameter that could cold-start a server.
- **kill_job wait:** kill_job now waits up to 3 s for an exit before answering. A SIGTERM-ignoring child gets `killed: false, status: 'stopping'`, and the existing 5 s SIGKILL escalation in background-jobs still runs.
- **SUMMARY_HEADER:** the model-visible header text in context-pruner ("This is a summary of the conversation so far…") is unchanged.
- **Docs:** no `docs/` page changes.
- **Edits in files owned by other workers or pre-modified by them:**

  - `cli/src/utils/sdk-event-handlers.ts`: `declinePendingCompactionBlocks` and its call site.
