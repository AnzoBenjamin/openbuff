# N08 — `/compact` and context controls

**Status:** implemented

Findings: memory-context-01, memory-context-04, memory-context-07. Probe `verification/probes/runtime/p6-compact.ts` now prints `findCommand(compact): compact`, and both `/compact` and `/compact keep the API notes` are sent to the agent (or queued while streaming). There is no "Command not found" any more.

## Changed files

- `cli/src/commands/command-registry.ts`: new `compact` command (`defineCommandWithArgs`). It sends `/compact` or `/compact <focus>` through `sendPromptCommand`, so the prompt is queued during a turn. Added next to `context`, and the other worker's `/provider` reset edit is untouched.
- `cli/src/data/slash-commands.ts`: menu entry for `compact`. The `context` description now mentions instruction files.
- `cli/src/commands/context.ts`: `/context` now includes an "Instruction files" section built from `fileContext.instructionFiles`, the ledger `instruction:<path>` labels, and the nested files already injected into history.
- `cli/src/types/chat.ts`, `cli/src/components/renderers/context-box.tsx`, `cli/src/utils/captured-diagnostic-document.ts`, `cli/src/utils/run-state-storage.ts`: added an optional `instructionFilesText` on the context block. It is rendered in the box and accepted by the saved-block validators.
- `cli/src/utils/sdk-event-handlers.ts`: the recovery text now says "run /compact [focus] to summarize the conversation".
- `packages/agent-runtime/src/system-prompt/prompts.ts`: added `parseCompactCommand` (accepts `compact`, `/compact` and `/compact <focus>`; prose like "compact the JSON" does not match) and `getAdditionalSystemPrompt`, which adds the focus instruction to the compact prompt.
- `packages/agent-runtime/src/run-agent-step.ts`:
  - The manual compact handler uses `parseCompactCommand`. It adds a `<compaction_focus>` block to the summary and pins it.
  - Nested instruction-file injection runs at each step for templates that carry the knowledge placeholders.
  - Overflow recovery: one retry per step, guarded by the committed-nothing check, with a semantic pass followed by a mechanical trim to min(50% of the request, 75% of the reported limit). It emits `context_compaction` and `provider_status: retrying`.
  - The recovery string now names `/compact [focus]`.
- `packages/agent-runtime/src/util/task-memory.ts`: `/compact <focus>` prompts are no longer recorded as the task goal.
- `packages/agent-runtime/src/util/context-overflow.ts` (new): overflow classifier. It recognises `context_length_exceeded`, the OpenAI/vLLM "maximum context length", Anthropic "prompt is too long", Gemini "exceeds the maximum number of tokens", vLLM "longer than the maximum model length" and "too long and exceeds limit", Ollama and llama.cpp "exceeds the (available) context length/size", the LM Studio "context the overflows", "context length of only" and "tokens to keep" messages, Bedrock "input is too long", and HTTP 413. It excludes 429 and rate-limit wording and reads the reported limit when the message has one.
- `packages/agent-runtime/src/util/nested-instruction-files.ts` (new): collects touched paths from tool-call path arguments. It builds one `NESTED_INSTRUCTION_FILES`-tagged message per newly governed nested file (plus that file's imports). The `<instruction_file path=...>` markers make each file inject once.
- `packages/agent-runtime/src/templates/strings.ts`:
  - `KNOWLEDGE_FILES_CONTENTS` and the `ROUTED_KNOWLEDGE_FILES` fallback render the always-on files: ancestor and project-root files plus their imports.
  - When ROUTER.md has a route, the routed files and their imports render within the task budget. All other always-on files follow, then the user files.
  - Duplicates are dropped by path and by identical content, so this repo's CLAUDE.md copy of AGENTS.md renders once.
  - Each rendered file is recorded in the ledger as `knowledge` / `instruction:<path>`.
  - Contexts without load records keep the old root-only rendering.
- `agents/base2/base2.ts` (N03-owned dir; one-line edit assigned to N08): removed `${PLACEHOLDER.KNOWLEDGE_FILES_CONTENTS}`. Base2 now renders only `ROUTED_KNOWLEDGE_FILES`, which ends the double injection.
- `common/src/util/instruction-files.ts` (new): record types, `@path` import extraction (skips code fences and code spans, absolute and `~` targets), always-on and nested selection, import expansion, content dedupe, and the `/context` formatter.
- `common/src/util/file.ts`: optional `instructionFiles` field on `ProjectFileContext` (type and zod schema).
- `sdk/src/instruction-files.ts` (new):
  - The loader finds the nearest `.git` boundary at or above cwd. Without one, no ancestor directory is read.
  - It loads every AGENTS.md, CLAUDE.md and knowledge.md in each ancestor directory, root first. It loads every knowledge file per project directory, marking root files `project` and subdirectory files `nested`.
  - It follows `@path` imports relative to the importing file, up to 5 hops and 32 files, skipping files over 100k chars. Imports must stay inside the boundary (path check and realpath check), and cycles are skipped through a visited/dedupe check.
- `sdk/src/run-state.ts`:
  - `deriveKnowledgeFiles` and `loadKnowledgeFilesFromPaths` now use the loader and also set `fileContext.instructionFiles`, both in `initialSessionState` and in `applyOverridesToSessionState`.
  - When the caller passes `knowledgeFiles` explicitly, the load records are dropped.
  - The other worker's project-skill trust edits are untouched. The legacy `selectKnowledgeFilePaths` and `selectHighestPriorityKnowledgeFile` exports are kept for their existing tests.
- Tests (new): `cli/src/commands/__tests__/router.test.ts`, `sdk/src/__tests__/run-state.test.ts`, `packages/agent-runtime/src/__tests__/run-agent-step.test.ts`.

## Not done / follow-ups

- `/compact` still uses the model-summary handler, as the scope asked. The finding's alternative (drive the extractive `context-pruner` with archiving) is not done. The manual handler also emits no `context_compaction` event (memory-context-01 fix item, memory-context-05).
- The SDK-layer retry in `sdk/src/impl/llm.ts` (N01/N07 territory) still matches only its three numeric wordings. The runtime handles everything else after the SDK gives up. When the SDK's trim retry already failed, the runtime retry is a second attempt overall.
- When the provider reports a smaller window, it is not saved to `contextWindowTokens`. A test showed that shrinking to 4096 makes the next step's emergency trim drop the recovered reply ("No response from agent"). If a later step overflows again, it gets its own single compact-and-retry.
- User files are still only `~/.knowledge.md`, `~/.AGENTS.md` and `~/.CLAUDE.md`. `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md` are not read (part of memory-context-04, outside the Accept line).
- The system prompt is still session-cached, so instruction-file edits made mid-session reach the model only through a new run's `applyOverridesToSessionState` refresh.
- `cli/src/agents/bundled-agents.generated.ts` was not regenerated. The base2 placeholder removal reaches the binary on the next `prebuild:agents`.
- Edits in files owned by other tasks: `agents/base2/base2.ts` (N03 dir), the one-line placeholder removal explicitly assigned to N08. `cli/src/commands/command-registry.ts`: one added command block. `sdk/src/run-state.ts`: knowledge-loading block only.
