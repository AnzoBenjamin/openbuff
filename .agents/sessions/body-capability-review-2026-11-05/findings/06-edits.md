**06-edits — observation authority, mutation execution and recovery**

Openbuff has a substantial editing body: authenticated observations, ordered transaction preflight, guarded mutation adapters, durable per-file receipts, group intent logging, semantic tools and workspace observers are connected to SDK and CLI consumers. The weak point is continuity of authority. Several paths discard the version, exact bytes, ownership or forward-commit evidence needed to make their later result trustworthy. Twelve findings are grounded in current code and bounded probes: seven HIGH and five MEDIUM. No source fixes were made.

| Capability | Maturity | Assurance | Practical boundary |
|---|---|---|---|
| Complete authenticated read authority | usable | static trace; read fixture | Complete scoped/whole-file grants, typed refusals |
| Byte fidelity | partial | integration | BOM and localized EOL variants fail |
| Coordinated multi-file editing | partial | integration | Atomic preflight; visible sequential commit |
| Cooperative broker/CAS receipts | partial | integration | Ordinary path works; takeover/recovery weaken authority |
| Group crash recovery | partial | integration | Durable intent exists; ownership/retry/admission gaps |
| Semantic WorkspaceEdit application | partial | protocol + integration | Versions, complete operation and snapshot are lost |
| Structural symbol rewrite | partial | static trace; tests inspected | AST/range authority; shallow foreign fallback |
| External-editor observation | partial | static trace; tests inspected | Debounced invalidation, no writer exclusion |

The discovery chain is real. `common/src/tools/list.ts:90` registers semantic tools and `:108` registers `edit_transaction`; `packages/agent-runtime/src/util/base2-tool-tiers.ts:69` exposes them in base2's implementation tier. Runtime handlers call `sdk/src/run.ts:2588` and `:3024`, which share `changeFiles`. The CLI consumes receipts at `cli/src/components/tools/edit-transaction.tsx:510` and semantic results at `semantic-edit-tools.tsx:186`. This is integrated machinery with defects, rather than an unused roadmap scaffold. Default base2 unlocks all non-core tiers; mode-policy defects are separately owned.

Useful existing guarantees should survive repair. `cap.v3` HMAC binds project, path, run and normalized observed text (`common/src/util/content-hash.ts:119`). Complete-only minting keeps partial reads from authorizing overwrites; destructive operations require whole-file coverage. Shared line coordinates distinguish the terminal empty entry, and reanchoring refuses ambiguity or its work budget. Pure transaction preflight stops on failure before client writes and preserves unaffected read authorization (`process-edit-transaction.ts:351`; recovery test `edit-transaction-multi-file-recovery.e2e.test.ts:232`). The ordinary coordinator refuses absent conditional primitives and rolls back with transaction-owned hash guards. Staged exclusive files, fsync, permission bits and bounded receipt retention are implemented.

**06-F1 · HIGH — competing stale breakers defeat cooperative CAS.** At `sdk/src/services/workspace-mutation-broker.ts:601`, an asynchronous stale decision is followed by unconditional removal of the current lock path. Another instance can acquire a fresh live generation in between. The fixture paused B after its stale decision and A before staging: both public conditional commits against the same original hash returned `applied=true`; A overwrote B's successful result. The probe widened existing awaits with internal DI and did not measure spontaneous race frequency. Repair needs generation-safe takeover serialized with acquisition. Acceptance: competing breakers must preserve a fresh live lock and permit exactly one commit from a shared preimage.

**06-F2 · HIGH — semantic edits adopt a later snapshot.** `language-intelligence.ts:350` reads and splices text, but `semantic-edit-apply.ts:136` forwards only path/new content. `change-file.ts:998` then snapshots current bytes and CAS-protects those newer bytes while committing content derived from the earlier read. A fixture external append disappeared, with `applied=true`. The multiplexer also discards document versions (`lsp-multiplexer.ts:1057,1318`): a framed peer's WorkspaceEdit version 999 applied against didOpen version 1. Preserve the exact source hash and document version across normalization, splice and apply. Acceptance: an intervening append, BOM/EOL-only change or mismatched version must reject without writes.

**06-F3 · HIGH — rollback conflict becomes false applied evidence.** The coordinator records an in-progress action before calling its adapter (`change-file.ts:687`), which is necessary for uncertain partial effects. However, `common/src/tools/results/filesystem.ts:1130` maps every `rollback_failed` to `applied`, and `:1105` treats it as confirmed. In the probe both forward CAS and rollback returned false; the surviving bytes belonged to an external writer, yet the action was confirmed applied. `sdk/src/run.ts:3184` consumes these actions for journal, LSP and observers. Keep forward evidence separate from attempted rollback and expose uncertain observations without promoting them. Acceptance: rejected forward/rollback calls produce zero confirmed actions and preserve foreign bytes.

**06-F4 · HIGH — startup recovery overwrites unowned divergence.** Intent entries contain preimages but no planned after-state (`transaction-intent-log.ts:161`). Recovery interprets any difference from old text as transaction divergence, restores mixed-state paths (`:1249`) and uses unconditional `writeFile`/`unlink` (`:1367`). A fixture's external work was overwritten by the preimage and recovery reported success. Read failure can fall back to unconditional restoration as well. Persist expected after-hashes and action evidence; use conditional recovery only for proven transaction-owned states. Acceptance: faulted group plus external edits must preserve those edits and remain unresolved when ownership is unknown. The probe exercised persisted interrupted state, without killing an OS process.

**06-F5 · HIGH — failed rollback is terminal.** After a restoration throws, `transaction-intent-log.ts:1263` still writes `tx_abort`; later scans consider only last-event `tx_begin` (`:1161`). Injected write failure left divergent bytes, but the next scan returned no pending transactions. SDK startup marks its once-per-process key before recovery and ignores its structured failure (`sdk/src/run.ts:965`). Persist a nonterminal recovery-required state, retain unfinished paths and mark successful startup recovery only after a conclusive result. Acceptance: fail once, recover filesystem availability, then retry successfully; restart must retain the unresolved intent and callers must see its state.

**06-F6 · HIGH — a partial WorkspaceEdit breaks interfaces.** Failed peer splices are removed while successful files survive (`language-intelligence.ts:418`). The apply core reports the surviving coordinator's success (`semantic-edit-apply.ts:94`). A declaration changed `foo` to `bar` while its failed consumer retained `foo`; output had `applied=true` plus an error. Unsupported resource operations are recorded as skipped but discarded by `lsp-multiplexer.ts:1171,1318`; another fixture omitted a requested file rename and applied text edits without any error. Preserve every operation/refusal and preflight the complete refactor. Acceptance: declaration/consumer/resource changes all complete, or all files remain untouched with a structured refusal. The CLI's partial label cannot restore interface consistency.

**06-F7 · MEDIUM — UTF-8 BOM preimages are not exact.** Default `TextDecoder` strips BOM in both `read-files.ts:297` and `change-file.ts:958`; the broker compares raw bytes. A BOM+CRLF file read returned `ok` and an anchor, but the reconstructed preimage hash could never authorize its actual bytes. Rereading repeats the mismatch. No fixture bytes changed, though rollback-incomplete was reported; false applied evidence is F3. Keep original bytes/BOM metadata authoritative and normalized freshness separate. Acceptance: ordinary read/edit/delete/move and rollback on BOM files preserve intended BOM, mode, untouched EOL and final-newline bytes with exact matching receipts.

**06-F8 · MEDIUM — scoped edits alter unrelated line endings.** `process-edit-transaction.ts:1241` builds range output from the whole LF-normalized snapshot; `:1319` does the same for symbol rewrite. A broker-backed one-line range edit converted all three CRLF terminators to LF. `str_replace` has original-line restoration (`process-str-replace.ts:991`) and its own mixed-EOL test, but other variants bypass it. Share a lossless localized splice/render path. Acceptance: every localized variant preserves byte equality outside its target across CRLF, mixed EOL, BOM, astral text and missing final newline. Only range conversion was executed; symbol conversion is directly inspected code evidence.

**06-F9 · MEDIUM — malformed server positions reach disk.** Normalization checks `typeof number` (`lsp-multiplexer.ts:1095`), and the offset conversion lacks nonnegative/integer checks (`language-intelligence.ts:262`) or ordered range validation. Negative characters on the second line edited the first; reversed ranges duplicated text and fractional offsets were truncated. A full fake-peer/multiplexer/service/apply case committed malformed text. Validate safe integer, nonnegative, ordered and line-content bounds, including CRLF. Default compliant LSP UTF-16 units match JavaScript; this does not prove alternate encoding support. Acceptance: malformed positions refuse without writes, valid astral UTF-16 positions preserve bytes, and other encodings are negotiated/converted or refused explicitly.

**06-F10 · MEDIUM — valid transactions silently lose durable recovery.** Mutation limits allow 16 MiB per file and 64 MiB rollback state (`common/src/actions.ts:17`), while the complete default intent log is capped at 8 MiB (`transaction-intent-log.ts:128`). `change-file.ts:658` proceeds when durable begin fails. A valid 9 MiB plus small-file group applied with neither intent log nor transaction ID; warning logging was the only degradation signal. A crash between commits would lack a group preimage, inferred from the observed missing record. Align durable admission or make an optional nondurable contract explicit. Acceptance: capacity/fsync refusal causes zero commits; accepted groups survive a killed/faulted mid-commit run.

**06-F11 · MEDIUM — bounded output hides unbounded line buffering.** `node-filesystem.ts:147,152,162` accumulates and concatenates complete lines before checking the returned-byte budget, including irrelevant lines. A 24 MiB unbroken fixture with a 1 KiB budget returned zero bytes but performed a 24 MiB concat. This instrumented allocation is evidence, not an RSS/throughput benchmark. Count skipped newlines without retaining their text, discard over-budget selected lines and add cancellation support. Acceptance: peak buffering remains within budget plus fixed chunk overhead, metadata stays honest, streams close on abort and incomplete reads mint no authority.

**06-F12 · HIGH — broker recovery escapes canonical containment.** `absoluteFromRelative` checks only lexical paths (`workspace-mutation-broker.ts:918`); recovered delete follows its current parent and unlinks staging (`:689`). Ordinary commits check parent realpath at `:899`. A legitimate pending delete was produced by a post-tombstone fault, its directory moved outside the fixture workspace, and its former parent replaced with a symlink. Fresh startup deleted the outside tombstone and finalized recovered committed. No receipt tampering occurred. Reauthorize recovered paths/identity and retain unresolved receipts on parent replacement. Acceptance: pending commit/delete/move recovery must neither observe nor mutate outside bytes after a parent symlink change.

Security, correctness, state mutation, error handling, performance, dependency hygiene, tests and API contracts were each considered. The concrete security failure is recovery containment, not a claim that cooperative locks provide an OS sandbox. Mutation code mostly uses Node filesystem/crypto and declared pinned `diff` 8.0.3; no undeclared dependency or CVE was established in this slice. Representative tests cover ordinary cross-process CAS, conditional rollback, cancellation, capability grants and semantic wrappers, while the reproduced boundary cases are missing or intentionally normalized away. Schema correlation and UI warnings are valuable but cannot repair false authority or incomplete effects after the fact.

External-editor observation is separate from exclusion. The CLI starts a debounced watcher, forwards exact SDK path deltas and falls back to stale marking for unknown effects (`create-run-config.ts:221,281,315`). Linux worker caps/unwatched directories rely on age sweeps; watcher failure remains best effort. SDK receipt-driven revision and LSP sync are wired (`run.ts:3189,3234`), but depend on F3's truth selector. Headless hosts need their own observation integration. These paths were statically traced; no live editor/OpenTUI test or sweep-latency measurement was run.

The repair queue should preserve the working system. First repair takeover, recovery containment and applied receipts in shared TypeScript authority. Then make group recovery ownership-bound, retryable and durably admitted. In parallel establish lossless UTF-8 snapshots/rendering, followed by complete versioned semantic edits with validated positions and a real interface/consumer build-test task. The streaming long-line fix is independent. A native or foreign implementation should enter only when a declared workload and measured boundary justify it; language migration does not supply discarded preimages or missing operation evidence. Detailed work packages, prerequisites, regression checks and stop rules are in the JSON report.

Inspection covers all eighteen picker ranges: fifteen primary files and 4,314 selected lines, with adjacent sampled ranges enumerated in JSON. Six disposable probe programs recorded seventeen scenarios under installed Bun 1.3.14; the repository pins 1.3.5. Native retrieval tools were unavailable, so discovery used the pinned picker, `rg` and exact reads. No full repository/CLI suite, live language-server polyglot task, Windows test, actual power loss, isolated install or performance baseline was performed. Grammar assets/lifecycle/navigation and existing provider/orchestration/sandbox defects remain separate ownership. This receipt establishes inspected evidence and limits, not whole-file completeness or a claim of best possible implementation.
