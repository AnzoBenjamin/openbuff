Openbuff already has a useful extension body: local executable agent definitions, original-schema SDK custom tools, versioned native overrides, real outgoing MCP dispatch, an incoming read/inspect MCP server, and protocol-peer MCP attachment. The main gaps concern information and authority crossing boundaries. Current result projection loses MCP failure/structured data; JSON can change MCP origin semantics; discovery imports auxiliary code; and module/schema transport can change a valid extension's meaning. These are repairable in TypeScript without postponing them for a language migration.

Existing strengths matter. MCP origins are held out of band in a WeakMap, rather than trusting a peer's `origin` property; client marks cannot be promoted on the same object (`common/src/mcp/client.ts:172–254`). Parsing propagates surviving marks before trusted blanket labeling. ACP ingests and attaches the same client-marked descriptor record, preserving identity on that direct path (`sdk/src/serve/bridge.ts:526–545,754–769`). Null-prototype record conversion protects own server/env/header keys. These are meaningful implemented boundaries, with current origin tests, rather than prompt requests to behave safely.

Tool grants also have real enforcement. SDK discovery applies explicit server/tool selectors, and the custom parser requires an own discovered descriptor (`tool-executor.ts:4021`). Configuring a server permits its discovered tools by default; explicit selectors narrow that surface. Concurrent `allSettled` discovery allows healthy servers to remain available when another fails (`packages/agent-runtime/src/mcp.ts:47–95`), while rejected list promises are evicted for retry. Provider construction preserves the original MCP JSON Schema instead of losing constraints through Zod conversion (`tools/prompts.ts:575–596`). SDK custom callbacks additionally retain their original schema at execution, applying asynchronous refinements, defaults and transforms to produce the promised Args (`sdk/src/run.ts:2406–2434`).

The incoming server is independently real. `openbuff mcp` binds filesystem, index and lexical memory seams before `runMcp` (`cli/src/commands/mcp-command.ts:57–122`). One listed-tool registry gates dispatch; unknown tools get structured MethodNotFound, handler failures get `isError`, and unavailable memory returns an explicit disabled observation. Optional `apply_edits` is both listed and dispatched only when mutations are armed. Mutation authority belongs to the broker reviewed elsewhere. The structural public server handle has an explicit declaration migration note instead of exposing incompatible MCP/Zod internals (`sdk/src/mcp/server.ts:487–506`).

Eleven current findings are ranked in the structured report. Each includes concrete source anchors, confidence, trigger, consequence, suggested repair and an acceptance probe.

1. **10-F1, HIGH — MCP failure and structured content disappear.** `callMCPTool` maps only `result.content` (`common/src/mcp/client.ts:862–902`). `isError:true` with empty content and useful `structuredContent` with empty content both became `[]` in the source-boundary probe. Text attached to a failure became an ordinary JSON string. The SDK returns this projection as normal output (`run.ts:2352–2364`), and the runtime publishes it as tool history. This prevents a model or host from reliably recovering from failure or inspecting structured evidence. Preserve a versioned full outcome, including failure, structured observations and provenance; assert those fields survive the full adapter/SDK/runtime path. Text resources also need meaningful text/media encoding rather than raw text masquerading as media data.

2. **10-F2, HIGH — origin semantics change across JSON.** A peer descriptor can be attached to a trusted local template, then included in the documented JSON RunState continuation (`sdk/src/run.ts:1075–1081`; `sdk/src/client.ts:46`). JSON loses the identity mark; template assembly uses aggregate `executionSource` and blanket-marks remaining local/bundled configs project (`agent-registry.ts:185–193`). The actual helper preserved client before JSON but promoted the same mixed-template descriptor after JSON. A later environment-reference resolution would regain local substitution and lose peer treatment. Conversely, actual supervisor reverse RPC received a project-marked config as unmarked/client (`parent-bridge-server.ts:1407–1408`), which can break legitimate substitution/authentication. Bind per-server provenance to parent-owned immutable identity or an authenticated reference across saved runs and RPC. No secret expansion or outbound exploit was performed; those effects are conditional downstream consequences of the proven mark change.

3. **10-F3, HIGH — discovery executes auxiliary modules.** With an explicitly trusted root or `agentsPath`, the SDK walker excludes only `skills`, `.d.ts` and `.test.ts` (`load-agents.ts:66–89`). Dynamic import precedes agent/id validation (`:193–208`). The real temp loader executed harmless marker modules in sessions, `__tests__/*.spec.ts`, node_modules, lib, types and `*.test.js`; it correctly skipped the three actual exclusions. A throwing module also disappeared with `validationErrors:[]`, matching CLI `validate:true, verbose:false`. This is not unconsented project execution: trust opt-in is required. It is excessive entrypoint discovery within that scope. Declare/narrow agent entrypoints, keep auxiliary dependencies importable by agents, and return structured import/walk diagnostics. A side-effect matrix must prove data/test/dependency artifacts are not discovery entrypoints.

4. **10-F4, MEDIUM — capability discovery is incomplete and stale.** The SDK consumes only the first `tools/list` page (`run.ts:1594–1611`); successful listings remain cached (`mcp/client.ts:830–843`). The fake two-page server was called once, the second-page selector found nothing, and a changed server still returned its original tools. Dispatch's rediscovery hits the same cache. Add bounded pagination, repeated-cursor/error handling, notification/reconnect invalidation and explicit generation/incomplete state. Preserve healthy-server isolation. Client eviction and close are a distinct pair09 issue.

5. **10-F5, MEDIUM — module dependencies are lost.** Local loading, SDK definitions and official prebuild convert `handleSteps` using `toString`; runtime `new Function` recreates global-scope text (`load-agents.ts:221`; `run-state.ts:146`; `prebuild-agents.ts:87`; `run-programmatic-step.ts:401`). A valid loaded generator capturing a module constant validated successfully and then raised ReferenceError. Wrappers duplicate constants inside generators to accommodate this constraint. Preserve trusted module/function references in process and use actual content-addressed dependency bundles for binary/process transport. The acceptance task must use imported helpers and captured configuration identically across all three paths. This addresses D53's actual integration gap without requiring first-party isolation.

6. **10-F6, MEDIUM — schema portability can silently weaken validation.** Native fallback and `unrepresentable:'any'` prioritize avoiding conversion crashes (`agent-validation.ts:500–547,623–665`) but do not expose degradation as a result capability. A required-object Zod husk accepted `{}` after rehydration; `z.never()` transported as `not:{}` subsequently accepted an object. A rich schema retained required/enum checks but accepted extra fields despite `additionalProperties:false`. The custom parser ignores parsed output and forwards original arguments (`tool-executor.ts:4062–4075`). Retain canonical JSON Schema validation or authenticated parent schema authority, with explicit unsupported/degraded states. Compare acceptance matrices, not just successful serialization or nonthrowing conversion; preserve original SDK refinement/transform checks.

7. **10-F7, MEDIUM — valid prompt constraints reject the whole agent.** Prompt-schema validation tests only the sentinel `"test"` and undefined (`agent-validation.ts:331–343`). String `minLength:5` and `enum:["work"]` were rejected despite accepting legitimate strings. Check the supported type structurally, then validate the actual invocation. The regression must load minLength/enum/pattern schemas excluding the sentinel and reject invalid prompts at call time.

8. **10-F8, MEDIUM — ordinary data is mistaken for filesystem authority.** Every collected custom/MCP string is normalized as a filesystem path when a project root exists (`tool-executor.ts:4201–4233`). `/api/v1`, `/` and a slash-delimited regex all triggered the escape predicate in the bounded probe. An API route or separator can therefore prevent a valid granted tool call. The source acknowledges false positives as a tradeoff; the resulting interoperability limitation remains observable. Use declared path/effect fields and authoritative handlers for real filesystem containment, while preserving exact other arguments. Keep the intended terminal/full-access policy and real filesystem protections.

9. **10-F9, MEDIUM — delimiter identity is ambiguous.** Discovery joins server/tool with `__`; dispatch interprets every name containing `__` as MCP and takes its first segment (`mcp.ts:71`; `tool-executor.ts:4288–4302`). Server `team__api` with tool `read` published `team__api__read` but decoded as `team` and `api__read`. Open custom names containing `__` also take the wrong dispatch path. Use explicit descriptor-kind/identity mapping and reversible provider IDs. Probe difficult server, tool and custom names through actual invocation, or reject unsupported names clearly during loading.

10. **10-F10, MEDIUM — wrapper receipts misstate enforcement.** The shared wrapper schema/prompt requires `permissionProfile:"tmux-test"` as runtime enforced (`cli-agent-schemas.ts:10–14`; `cli-agent-prompts.ts:360`). The actual shared producer deliberately stamps `full-access` for every terminal call (`handlers/tool/run-terminal-command.ts:38–42`). External Codex/Claude/Gemini flags are separate. Derive effective-profile fields from runtime evidence and report the real posture. This is a receipt-truth repair, not a recommendation to reverse the user's full-access preference.

11. **10-F11, LOW — the guide claims nonexistent isolation.** `docs/agents-and-tools.md:11` says secure sandbox; the executor uses the host realm, and the existing test explicitly documents host-global visibility (`sandbox-generator.test.ts:163`). Remote executable templates are refused (`sdk/src/impl/database.ts:288–298`), not sent to QuickJS. Document trusted host authority accurately and advertise an optional untrusted isolate only when it has an implemented consumer and verified boundary.
