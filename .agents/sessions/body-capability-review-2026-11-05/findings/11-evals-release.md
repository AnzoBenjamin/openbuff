# Evals, learning evidence, and release assurance

Openbuff has useful evaluator and release machinery, but it does not yet demonstrate a measured learning loop. The strongest problem is outcome truth: an SDK failure can become a measured success, and a cancelled validation can keep executing. Those defects must be repaired before statistics, accumulated lessons, or a future routing policy can be trusted. The current lesson promotion path deliberately rejects a single-run comparison; that is a useful safety property, not evidence of adopted improvement.

This review is bound to snapshot `ec141833a7efa94cd25b0e2c964fc2c832ce5983b2446c03769515032360deb0`. It covers all 18 required picker sections, with 102 recorded bounded reads across 90 files and a structural receipt of 88 current inventory members. Supplemental `cli/release/index.js` and its public package manifest were read as context and excluded from that receipt. The JSON contains detailed evidence, states, limits, and six executable work packages.

The evaluator really clones/checks out a repository, calls a runner, gathers its diff/context, runs final checks, and dispatches two structured judges. It supports independent bounded checks, declared prerequisites, input-order results, and configuration-error, skipped, timeout, and cancellation outcomes. Judges validate score schemas, preserve individual scores, distinguish total/partial judge failure, and clamp scores on failed compile/test/lint checks. Empty validation means no deterministic information; it is not a pass. Final checks are optional repository commands visible to the coding agent, so they are not protected held-out correctness tests.

## Existing strengths and assurance limits

The production memory playbook callback is genuinely wired from SDK repository configuration into tool-gate observations and persisted counters. Throwing/rejecting reporters are isolated from tool dispatch. Knowledge routing and configured provider routing also have real consumers. These mechanisms can influence subsequent context, but fired/complied counts, Markdown lessons, and a task-type router do not establish held-out behavior improvement. Extraction defaults off, inspected default/nightly callers do not enable it, and the live proposal gate intentionally constructs zero deltas with no paired baseline. Candidate execution, measured adoption, rollback, and learned model routing are absent from the traced consumer chain.

CI has meaningful blocking generated-source/config/environment/types/provenance guards, frozen Bun 1.3.5 installs, full-package unit discovery including TSX, empty-discovery rejection, and retry attempt artifacts. Its performance driver separates comparable rows from structural contracts and noise envelopes; selected pathological bounds are real. The scaled CI smoke mainly asserts completion and positive timings, so it does not establish a general task-success/latency/cost/heap regression budget. Integration discovery permits an empty set. Static Rust host build/test is unconditional, but boolean/string matrix predicates and the stale native exec-smoke expectation remain pair09-owned; actual GitHub execution is unknown.

SDK build checks both Node bundle conditions and selected public exports after repairs, disables build-time environment inlining, and separates runtime dependencies from typings. Compatibility projects execute Node imports and some compiled constructor/type examples. Their dist copies/file references remain inside repository ancestry, and smoke forces asset paths. They do not prove a tarball-only installed observe/edit/validate/cancel task across the declared Node minimum. CLI release smoke uses temporary directories and native/boot probes; the supplemental wrapper has checksums, extraction checks, rollback, update backoff, and careful offline version healing. Its tests inject probe/download seams rather than execute an installed binary. Concrete query/grammar omissions belong pair07.

All eight domains were assessed: security boundaries and paths; correctness/oracle/population truth; state ownership and cleanup; error/cancellation/retry settlement; bounded performance and missing budgets; dependency/provenance scope; meaningful versus mocked test assurance; and runner/metadata/public package contracts. The root SCM preload removal matches current filesystem query loading and is not an import defect. The registered Infisical/Nx executor has bounded cwd/env input but no active consumer found in inspected commands; treat it as an unwired maintenance surface, not a shipping body capability.
