# Execution as a model body — pair09

Openbuff can run ordinary project commands, create owned background jobs, stream bounded observations, and apply a real standalone Linux filesystem restriction. Its most consequential gaps sit between action selection and confirmed effect completion: the retained approval gate misses executable forms, several nonterminal launchers inherit provider credentials, and process settlement can leave work alive after timeout or kill. These are repairs to present machinery, not reasons to replace the whole runtime or to count new implementation languages as progress.

The bundled runtime deliberately sets `permission_profile: 'full-access'` for every agent (`packages/agent-runtime/src/tools/handlers/tool/run-terminal-command.ts:38`). Its tests explicitly require this even for narrower templates. Unbounded productive wall-clock defaults and unrestricted network posture are also intentional. This report preserves those choices. It assesses separately the high-impact approval gate, explicit finite options, host-selected SDK profiles, secret handling, resource ownership and promised sandbox tiers. The SDK comment at `sdk/src/run.ts:2624` still says templates clamp authority; that comment and basher profile commentary need reconciliation with current behavior, not renewed restrictions.

| Owned Chrome processes / transport fallback | Partial | Pipe-first launch, rollback and owner teardown statically traced |

The main action chain is model tool call → runtime handler → SDK dispatch → `runTerminalCommand` → Bash or background adapter → shared job registry. Validation diverges: configured hooks call the terminal helper directly, while diagnostic delta, LSP and discovery/index adapters launch argv processes through other seams. MCP has its own cached dependency transport; Chrome has a separate session manager. There is no common execution scope carrying environment delegation, approval, deadline choice, cancellation and observed process-tree settlement across all these consumers.

## Ranked findings

**09-F1 — HIGH: semantic whitespace is removed before classification and approval hashing.** `harness-enforcement.ts:153,162,649` collapses every whitespace run before the scanner that is supposed to split executable newlines. The harmless command `printf safe` followed by a newline and a Python one-liner printed both statements with **zero authorization calls**. Quoted Node payloads printing `a  b` and `a b` also produced identical action, target and hash. The scope lock and snapshot check cannot compensate for an identity function that conflates different executable bytes. Basher's full-log producer itself constructs multiline wrappers (`agents/basher.ts:196-233`), so newline handling matters in normal workflows. Hash exact bytes and parse the original text; acceptance must reject semantic whitespace collisions and authorize later newline-separated effects.

**09-F2 — HIGH: a routine first effect hides later risky effects.** `harness-enforcement.ts:425-434` returns the first classified segment. Probes of a package operation followed by recursive deletion, and a feature push followed by Terraform, returned a routine action with `approvalRequired:false` under balanced mode. No destructive or remote probe command was executed. The failure is the production decision itself: later effects never reach policy. Represent every executable effect and evaluate the complete immutable plan. Ordering, shell wrappers and substitutions must not change whether a risky effect is governed.

**09-F3 — HIGH: feature-branch force/delete pushes become routine.** Push parsing retains branch and target but discards destructive risk attributes (`harness-enforcement.ts:174-198`). Balanced policy only recognizes a push needing approval when its branch matches a known default (`:719-733`). Both `git push --force origin feature` and `git push --delete origin feature` were therefore allowed without approval in pure probes. This contradicts the explicit retained force/delete gate in `docs/agents-and-tools.md:66`. Test destructive flags, refspec forms and ambiguous upstream targets across all three modes while preserving ordinary feature work and explicit allow-all behavior.

**09-F4 — HIGH: adjacent launchers inherit canonical provider keys.** The terminal merges then re-scrubs caller overrides (`run-terminal-command.ts:1525`); its synthetic child saw neither canonical sentinel. The compiler adapter instead inherits or merges `getSystemProcessEnv()` (`diagnostic-delta-runner.ts:122-126`), and its Python child saw the host sentinel or supplied override respectively. LSP (`language-intelligence.ts:615`), Chrome (`browser-logs.ts:1484`), version probes (`harness-intelligence.ts:552`) and SCIP (`scip-runner.ts:322`) omit explicit environments. Apply a shared child-environment contract to implicit host inheritance and re-scrub merges. Preserve ordinary project variables and intentional server-specific credential delegation rather than indiscriminately deleting all user environment variables.

**09-F5 — HIGH: leader exit cancels descendant cleanup.** SYNC close clears its KILL timer (`run-terminal-command.ts:1663-1673`); background settlement similarly clears escalation (`background-jobs.ts:497`) and leader exit reports stopped. A redirected Python descendant ignored TERM and remained in Linux sleeping state after 5.5 seconds. SYNC returned timedOut; BACKGROUND reported stopped, then refused a subsequent SIGKILL because it was settled (`:1257`). These were normal process-group children, not deliberately escaped sessions. Keep scope supervision alive after leader exit and claim completion only when the owned scope is empty or explicitly uncertain. Repeat timeout, abort and kill probes with redirected TERM-resistant children.

**09-F6 — MEDIUM: quota failure removes authority to kill a live job.** The quota path settles terminal error before sending TERM and schedules no KILL escalation (`background-jobs.ts:798-804`). The probe retained exactly the intended 10 MiB tail but its TERM-resistant process remained sleeping after 5.5 seconds; a job SIGKILL returned `killed:false`. Existing quota tests (`run-terminal-command.test.ts:290`) assert error and log size, not process death. Keep failure reason separate from liveness and retain kill authority during cleanup. The acceptance probe must demonstrate both bounded logs and a dead process scope.

**09-F7 — MEDIUM: MCP eviction abandons transports.** The claimed 64-client cap deletes registry/cache entries without closing the evicted client (`common/src/mcp/client.ts:51-65`). Replacing the ESM connect method before import allowed 65 real Client objects to be registered with **zero close calls**, without starting any transport. Real-process leakage is inferred from that path and the dependency transport lifecycle; 65 live subprocesses were not created. Use leases/disposal so idle eviction closes resources and active requests are not accidentally killed. A connection-count bound must become an observable resource bound.

**09-F8 — MEDIUM: configured hooks lack approval context.** Hooks call the terminal helper without its authorizer or a host-selected profile (`file-change-hooks.ts:1585-1608`), and both SDK hook dispatch and targeted validation use that path. A configured harmless Python print one-liner returned `approvalRequired:true`, `permissionDenied:true`, and `workspace-write`. There is no hook-route callback to request approval or consume the run's receipt. Thread explicit host execution policy and authorization through this path, retaining configured/inferred trust distinctions and profile-preserving reruns. Test granted, declined, unavailable and already-authorized states.

**09-F9 — MEDIUM: native smoke still tests a stub.** Fresh locked/offline build succeeded, but the current smoke expects `exec` to exit 2 with `not_implemented` (`rust/scripts/smoke-test-sidecar.sh:45-52`). The implemented role receives EOF and exits 1. Actual local output passed version and unknown-role checks, then reported “exec exited 1, expected 2.” The workflow references this smoke, but boolean matrix flags (`rust-workspace.yml:74,93`) are compared to string `'true'` (`:129,135`); actual CI execution may be skipped and was not verified. Repair the script and typed guards, then require a receipt showing the host-native checks actually ran.

**09-F10 — LOW: a sidecar's previous stop promise survives explicit reuse.** `start()` permits stopped instances, but `stop()` only invokes cleanup when its lifetime `stopPromise` is null (`sidecar-supervisor.ts:147,190,255`). A later start resets `stopRequested`, not that promise (`:281`). The second stop therefore awaits already-completed cleanup for the old child and does nothing to the new child. Exposure is limited because no default constructor consumer was found. Reset memoization by child generation or prohibit explicit reuse. This finding is static control-flow evidence: a local Bun/Python fake handshake timed out and is not counted as successful behavioral assurance.

## Strengths worth preserving

The approval store holds read/consume under a kind lock, verifies workspace/run/snapshot/action/target/hash, rejects malformed expiry and consumes once (`harness-enforcement.ts:86-123`). Approved terminal reruns keep assistant mode and profile, rechecking cwd rather than bypassing the helper as user mode. Runtime-injected owners override model inputs, and foreign-owner kill is rejected before OS signaling. Background jobs provide real incremental UTF-8 observations, bounded event rings, live UI forwarding, owned cancellation and explicit detach. These are substantive body capabilities, not merely agent instructions.

Output handling is also useful: bounded head/tail capture retains startup and recent context; a disk spool preserves overflow with backpressure and recovery paths. Compiler capture measures bytes and decodes after accumulation. Hooks distinguish no configured checks from skipped checks and propagate cancellation after concurrent settlement. Chrome uses private temporary profiles, prefers private CDP pipes, rolls back failed starts and protects stop-versus-spawn registration. Its Linux no-sandbox fallback is deliberately documented and tested; this audit does not redefine that preference as a defect.

The native slice is real. The fresh binary handshook, forwarded a harmless target and reported explicit degraded status when Landlock was disabled. With Landlock enabled it allowed reads/writes inside the fixture allowlist and denied excluded fixture access with errno 13. Root's supplied Rust log contains 19 passing tests. This proves standalone Linux filesystem enforcement, while its unit test alone only accepts successful ruleset creation regardless of kernel support. It does not prove D48 network, Unix-socket or syscall isolation.

## Native adoption and cross-language boundary

Current Rust exec expects initialize followed by a raw top-level ExecPlan, then replaces itself with a process whose output is ordinary target bytes. The generic TypeScript supervisor sends correlated JSON-RPC method/params envelopes. A direct receiver probe completed handshake but rejected that envelope with missing top-level `cmd`; it has no compatible request/result channel after exec. No actual CLI/SDK plan producer, verified-artifact launcher or enforcement-status consumer appeared in the bounded production search. The default capability map honestly says lexical, unenforced, unrestricted network and no sidecars (`common/src/protocol/acp-ext-v1.ts:293`).

Latest historical D48 requires Linux bubblewrap plus seccomp with BestEffort Landlock, macOS Seatbelt, and Windows restricted token/user/ACL/firewall work. The current ABI V1 Landlock-only role does not supply those tiers. Its plan has no cwd, network or deadline fields; partially enforced rulesets also collapse to the same boolean as fully enforced ones. D49's multi-call artifact exists, while daemon and other remaining roles still fail loudly as unimplemented. Download verification and generic supervision are useful pieces, but a readable 0600 cached artifact, version handshake and green build are not installed execution integration. Interactive task PTY, stdin/resize/attach and persistent native job supervision remain absent.

## Eight-domain assessment and limits

Security findings concern retained approval/credential promises, not unrestricted defaults. Correctness and state mutation center on authority identities, live resource settlement, hook routing and reuse. Error handling has good explicit denial/timeout/skipped states, but cleanup often lacks observed scope exit. Performance has meaningful byte/event/log bounds; MCP eviction and quota termination fail to bound live work. Successful SYNC spools have no inspected aggregate retention quota, and LSP's unexposed stderr pipe suggests backpressure risk; neither is presented as a measured benchmark.

Dependency review found declared MCP caret ranges and an installed 1.20.2 implementation. That transport inherits a small safe default environment plus explicit server env, closes failed initialization and supplies a 60-second request default. Accordingly, no blanket MCP credential-inheritance, missing-timeout or failed-initialize-leak claim is made. Rust toolchain is pinned at 1.87.0 and the build was locked/offline. No vulnerability advisory scan or CVE assertion was attempted. Test coverage and API contracts are addressed in each finding; existing tests were inspected rather than rerun as broad effectful suites.

All 18 primary and 46 secondary picker sections were read, with adjacent consumers/manifests added. The JSON supplies exact merged source ranges, all eight domains and only inventory-current files in its structural receipt. Native audit tools were unavailable: cached retrieval provided navigation, followed by current numbered reads and bounded searches. No private configuration, credential values, external requests or real-user process effects were used. Resistant children had a fixed self-exit and verified owned-PID cleanup; TMPDIR isolated job logs and sweeps, and the cleanup receipt reports no known fixture still running. Windows/macOS, real Chrome/LSP, live remote MCP and recovery PID reuse remain untested. Neighboring shards own mutation/recovery, language semantics, plugin trust, distribution and browser interaction quality.

Repair the current TS approval identity/aggregation and process-scope/env/hook contracts first. Then close cached resources and define supervisor generation semantics. Fix native smoke immediately, but gate native graduation on one actual installed producer-to-consumer path carrying exact policy, cwd/env, lifecycle, output and honest enforcement status. Keep the standalone working slice and the user's full-access defaults; defer broader Rust/PTY/daemon work until its concrete consumer and behavioral acceptance evidence exist.
