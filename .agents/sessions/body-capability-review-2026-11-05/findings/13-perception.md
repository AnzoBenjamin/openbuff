## Vertical trace and valuable existing behavior

The browser specialist is wired from `agents/browser-use/browser-use.ts:156` through the runtime handler and `sdk/src/run.ts:2838` to actual CDP operations. Click, real keyboard/text insertion, hover, drag, selection, upload, tabs, viewport and network emulation exist. Its final structured results reach the CLI formatter at `cli/src/utils/message-block-helpers.ts:705`. This is a substantial action body, rather than an instruction to simulate browsing.

The usual transport uses private pipe descriptors, with timeout/correlation/backpressure handling in `cdp-pipe-transport.ts:126`. Browser probe, startup and reconnect work is deduplicated. Stop markers cover startup/teardown races, and failed directory cleanup is deferred for later reclamation. These mechanisms deserve preservation. Generic child environments, kill guarantees, sandbox policy and approval behavior are pair09 responsibilities.

Screenshot actions return actual image media. Recording has a finite frame cap and rollback when starting fails. Logs, network events and tracked requests are bounded; response windows handle concurrent cursor movement and trimming. Empty captures expose attachment flags instead of attaching empty bytes. However, snapshots sample 200 matching DOM elements and 12,000 text characters without a completeness marker or visibility filter. PDF captures return only length metadata; the PDF bytes cannot subsequently be inspected. APNG recordings lack a retained artifact route and the CLI inline renderer excludes their MIME type. Several schema controls, including retries, log filtering and visual verification, are accepted but unused. The load helper catches wait failures and approximates network idle with a 750ms delay (`browser-logs.ts:2336`).

Native image reads use the read-specific scoped resolver and host filter, preserve original bytes, and return per-path metadata alongside media. The 25MiB attachment budget is deterministic in input order. It is applied after all concurrent reads, so it does not bound peak read work. Cancellation is checked before each image's asynchronous path resolution, not after reading. Actual-byte size, decoded format and stable content provenance remain limited; provider vision routing is pair02.

CLI attachments keep processing/ready/error states, original source information and an attachment identity fence against stale asynchronous completion. Normal submission waits for processing. Send preparation atomically drains attachments and sends cached processed bytes, avoiding a second capture from disk. Conversation ownership is checked after asynchronous preparation. Image display provides unsupported-terminal, empty, decode-failure and saved-state redaction explanations plus retained-source inspection. Failed retry handling is weaker at the final media projection, as F8 establishes.

The link widget has a concrete registry consumer, controlled theme colors, duplicate-activation prevention and generation guards. Failed launch or clipboard copy leaves the destination available. Its successful wording is “Browser launch requested,” which accurately describes the host effect. Its scope is one http(s) button, not an arbitrary HTML or desktop UI renderer.

3D discovery preserves assets as metadata-only tree nodes. The indexer verifies source hashes before admitting derived concepts (`metadata-indexer.ts:943`). Native glTF/GLB/OBJ inspection produces useful names, counts and transforms without Blender. It is shallower than geometry, material, rigging or scene semantics. Blender scripts are fixed, disable blend-file autoexecution, limit output/time and surface nonzero/Python failures. SDK dispatch rejects filesystem adapters explicitly declaring a different host process view.

The .blend edit path copies the hashed bytes into exclusive attempt-scoped files, accepts four declarative operation types, reopens before conditional commit, and separates applied, not-applied and unknown commit results. Unknown commits retain their working copy for reconciliation. Failed retries cannot remove earlier attempt files. These are valuable mutation guarantees. Recent artifact protection and pruning are bounded, although lifetime/expiry is not returned to the consumer. Common mutation-broker authority is pair06.

Engine detection feeds actual slash-palette prompt insertion and system-prompt guidance. This helps projects cooperate across C#, GDScript, C++ and Rust without introducing another execution authority. `getGameDevJobGuidance` has only tests/docs references in the scoped production search, despite docs claiming runtime consumption. Weak directory heuristics also lack confidence labels. These helpers are recipes over existing tools, not engine-specific session, asset or build operation bundles.

## Findings

**13-F1 — MEDIUM: policy contracts drift.** Evidence: `browser-use.ts:46`, shared `browser-policy.ts:46`, handler `browser-logs.ts:39,68`. An omitted policy can be restricted despite the schema/prompt's allow-interactions default. Explicit read-only scroll, design_tokens and tab-list inspection are unconditionally rejected by the handler despite the shared allowlist. Tests encode both defaults. This creates avoidable respawn/authorization loops. Use one structural policy evaluator, including recursive diagnose and tab operations. Probe the full executor-to-handler path across omitted/read-only/allowed/plan-only cases; denied mutations must stay denied. Default application during spawning was not exercised here.

**13-F2 — HIGH: browser child ownership is lost.** Evidence: runtime handler `browser-logs.ts:95`; SDK `run.ts:1097,2847,2851`; browser key `browser-logs.ts:122`. The SDK correctly rejects spoofed input but replaces genuine child stamps with one main-run owner. Concurrent children therefore resolve to the same session. Cleanup also selects the entire client ID and all ownerless sessions (`run.ts:1853`, `browser-logs.ts:2002`). Interference between concurrent callers is inferred from these static predicates, not a live race. Carry trusted child identity outside model input; clean up the exact root's sessions. Probe two children and two roots, preserving spoof resistance and sibling state.

**13-F3 — MEDIUM: diagnose loses observations.** Evidence: `browser-logs.ts:570,575,583`; conditions schema `browser-actions.ts:546`. A screenshot step is reduced to JSON, discarding image media; conditions are copied rather than evaluated. The fake-CDP probe returned screenshotAttached:true and zero media, with outer success:true and an explicitly failed nested action. Nested errors remain readable; outer success proves sequence dispatch only. Preserve or reference step media and provide explicit condition/aggregate outcomes. Acceptance requires accessible screenshot evidence and failed/unsupported condition verdicts, not echoed expectations.

**13-F4 — MEDIUM: pixel diff omits image extent.** Evidence: `browser-logs.ts:3338,3342,3350`. The comparison crops to minimum dimensions. A 2×1 actual versus 1×1 expected fixture, with a different extra pixel, reports mismatchRatio:0 across one pixel. Original dimensions are exposed, so callers could detect the discrepancy separately, but the headline statistic is incomplete. Default to explicit dimension mismatch or a padded union; make intersection-only comparison an explicitly partial mode. The fixture must cease implying a complete zero difference under default comparison.

**13-F5 — MEDIUM: advertised preview formats lack import branches.** Evidence: format registry `file.ts:24`; preview schema `3d-assets.ts:31`; SDK script `3d-assets.ts:154,183,816`. Successfully inspected glTF, GLB and OBJ cannot preview through the fixed importer; discovered 3ds also has no branch. The script necessarily raises an unavailable-importer error. Add tested operators for declared Blender versions and expose per-format/per-operation availability before effects. Acceptance requires inspect-plus-preview fixtures for glTF/GLB/OBJ, plus honest missing-Blender/operator results. Actual Blender compatibility was not executed or measured.

**13-F6 — HIGH: exact preview provenance is unproven.** Evidence: SDK `3d-assets.ts:617,825,837,865,868`; documented exactness `architecture.md:173`. The SDK hashes initial source bytes, then Blender reopens the live path. If an editor replaces the asset in that interval, the resulting preview can carry the earlier hash. That wrong-revision outcome is conditional inference; the separated read/open/receipt steps are direct static evidence. Dimensions are also copied from requested values rather than decoded output. Render an immutable verified snapshot and bind receipts/media to observed PNG bytes. Acceptance must inject replacement and require the original snapshot or explicit stale evidence; dimensions must come from the actual PNG.

**13-F7 — MEDIUM: preview failure is marked rendered.** Evidence: `3d-assets.ts:888,1318,1384`. After a commit, a cancelled or failed preview returns error JSON. The edit checks only whether any JSON part exists, so previewRendered becomes true even though preview.error is present. The applied edit and artifact remain correctly preserved. Compute rendered state from successful validated artifacts/media and distinguish attachment failure. A commit-then-preview-error fixture must retain outcome:applied and artifactPath while returning previewRendered:false. This combined path was statically traced, not executed with Blender.

**13-F8 — MEDIUM: failed image retry sends old bytes.** Evidence: `pending-attachments.ts:651`, `image-processor.ts:51,89`, send consumer `use-send-message.ts:783`. Retry preserves a prior capture while setting status:error, but message preparation accepts processedImage regardless of status. The production-helper probe confirmed that failed clipboard retry still emits one image part. The model receives an observation the user intended to refresh, without a stale/reuse indicator. Gate sending on ready state; preserve old bytes for inspection and offer explicit, labeled reuse. Acceptance must omit/reject the failed capture or require that reuse decision.

**13-F9 — MEDIUM: render_ui acknowledges an unobserved render.** Evidence: runtime `render-ui.ts:14`, schema `render-ui.ts:54`, CLI registry `registry.ts:136`. The handler says “UI rendered” without a host capability or acknowledgement. A headless SDK host exposing the tool can therefore report rendering despite having no renderer. This is static host-wiring evidence; no model/headless task was run. Distinguish widget submission from actual delivery/rendering. Acceptance requires truthful unsupported/submitted status without a renderer and actual CLI button acknowledgement where available.

## Eight-domain assessment and executable priorities

Security inspection found worthwhile scoped image reads, input-owner spoof rejection and fixed Blender scripts; generic sandbox/trust findings belong to pairs09/10. Correctness findings concern observable result meaning, format coverage and policy drift. State mutation concentrates on browser ownership, capture identity and hash-before-reopen provenance. Error handling preserves useful per-action/unknown-commit states but mislabels preview success. Performance has explicit caps, alongside unbounded image read fan-out and incomplete observation pagination; no timing or memory measurement is claimed. Dependency inspection confirmed declared pngjs/pixelmatch/ws and Jimp/open/OpenTUI packages; no network vulnerability audit occurred. Coverage has useful parser/transport/state tests but misses integrated ownership and failure-result contracts. API contracts diverge across policy, render acknowledgements, preview booleans and format advertising.

The ready queue should repair TypeScript before expanding surfaces. First unify browser policy and authenticated child ownership; retain full-access product preferences and existing transport safeguards. Second make media/diagnose/diff/render acknowledgements describe delivered evidence. Third fix image retry projection and bounded post-I/O cancellation/size admission. These changes can use the current offline fixtures as regressions, supplemented by actual host-consumer tests.

Then make 3D operation availability explicit, stage trustworthy source evidence, decode artifacts, and test applied edits with preview failure. Depend on the existing mutation authority rather than adding a second broker. Stop short of advertising a format until its inspect/render workload passes on the chosen Blender version. Integrate engine job guidance into a real consumer or retire its consumption claim; defer richer editor/asset bundles until a concrete workflow requires them.

Desktop and voice require separate workload decisions. OS APIs may justify a Rust adapter; local speech libraries may justify another component. Graduate only a negotiated callable path with observations, actions, permissions, cancellation, ownership and platform tests. A role name, dependency addition, provider audio field or passing stub test cannot complete that work.
