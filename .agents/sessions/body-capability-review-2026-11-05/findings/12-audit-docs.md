**12 — Audit, capability, harness evidence, and documentation review**

Openbuff has a substantial body for coding work: local SDK dispatch, typed tool descriptors, configurable agent templates, specialist roles, environment discovery, bounded review bundles, validation hooks, durable plan artifacts, and an exclusive audit writer. Those are useful foundations. Their existence does not establish executable feature completeness, safe continuation, or learning. The main problem in this slice is that several evidence boundaries accept declarations or incomplete identities as stronger proof than they provide.

This report records eight findings: three HIGH and five MEDIUM. Two isolated local probes exercised the real SDK audit wrappers, review-bundle identity, targeted validation, store consumption, and exported reviewer gate helpers. No model, network, private configuration, or existing private logs were used. Source files were not changed. Root’s existing unimplemented-feature and native snapshot probes were reused without rerunning them. The JSON companion records exact inspected ranges and distinguishes structural receipt files from external review context.

**Findings**

1. **12-F6, HIGH — Targeted validation misses equal-length changes beyond an untracked file’s first 1 MiB.** [The identity reader](/home/ben/Code/CLI/openbuff/sdk/src/tools/get-change-review-bundle.ts:393) hashes file size plus a capped prefix. Untracked content does not appear in the tracked Git diff. A 1,200,028-byte fixture changed its exported value beyond that prefix while keeping its length; the bundle snapshot remained identical and `truncated` remained false. An injected hook changed the same tail during [targeted validation](/home/ben/Code/CLI/openbuff/sdk/src/tools/run-targeted-validation.ts:94), which returned `status: passed` and `assurance: full`. This proves an incorrect source-binding result, rather than an actual target-project test passing. Hash full contents incrementally, or reject source attestation when identity is incomplete. Acceptance must change the snapshot for an equal-length tail edit and reject a mid-validation edit while preserving bounded memory and successful unchanged-source controls.

2. **12-F3, HIGH — A foreign reviewer fingerprint is accepted and can be recorded under the expected identity.** [Attestation](/home/ben/Code/CLI/openbuff/agents/base2/gate-reviewer.ts:292) explicitly accepts any well-formed foreign `v3:` token when the declared file roster covers pending files. The probe returned no attestation issues, no blockers, and `LOOKS_GOOD`; the foreign token became drift telemetry. [The caller](/home/ben/Code/CLI/openbuff/agents/base2/base2.ts:6431) records that telemetry and continues. [Receipt persistence](/home/ben/Code/CLI/openbuff/agents/base2/base2.ts:13000) uses the parent’s expected fingerprint for `gateId` and samples file hashes at credit time; neither demonstrates which bytes the reviewer inspected. This is an intentional current tolerance, covered by tests, rather than a forgotten comparison. The risk is relabeling an obsolete assessment as evidence for the expected source. The probe establishes helper acceptance and static credit wiring; it did not run a live model review. Permit unrelated metadata changes through a stable content identity, while requiring the reviewed file basis to match. An old verdict over the same paths with changed bytes must require review again.

3. **12-F5, HIGH — Omitted `autoFileChangeHooks` enables inference despite the explicit trust opt-in.** [Configuration](/home/ben/Code/CLI/openbuff/sdk/src/provider-config.ts:514) describes inference as disabled by default, but the empty default leaves the value undefined. [Hook selection](/home/ben/Code/CLI/openbuff/sdk/src/tools/file-change-hooks.ts:1538) suppresses inference only for false, and [SDK dispatch](/home/ben/Code/CLI/openbuff/sdk/src/run.ts:2908) supplies no normalization or hook override. A Rust manifest therefore selects Cargo clippy/test commands for changed Rust files without `autoFileChangeHooks: true`; these commands can run repository build scripts and tests. This conclusion is a static production trace; no untrusted build was executed. Require explicit true for inference and keep configured hooks available separately. Also reconcile the timeout contract: hooks currently default to 300 seconds, while public prose and a schema comment claim no default timeout. A harmless captured-runner fixture should distinguish omitted, false, and true, and verify actual timeout forwarding.

4. **12-F1, MEDIUM — Nested feature snapshot identity is discarded.** The input schema requires each feature receipt to carry `snapshot_id`, but [SDK normalization](/home/ben/Code/CLI/openbuff/sdk/src/tools/audit-intelligence.ts:137) drops it. The coverage service never compares it with the outer inventory. A schema-valid foreign feature snapshot returned `complete: true` alongside current structural receipts. Preserve and verify nested identities before examining evidence categories. The acceptance probe should mix old feature evidence with current structural evidence and receive a specific identity error; a fully matching control should retain its present behavior.

5. **12-F2, MEDIUM — Cached audit inventories suppress stale-source refusal.** [Both SDK audit wrappers](/home/ben/Code/CLI/openbuff/sdk/src/tools/audit-intelligence.ts:116) accept a same-root cache entry without recomputing source identity. The stale check runs only on a cache miss. After changing a small inventoried implementation below every byte cap, a fresh inventory produced a different hash, yet coverage against the cached inventory still returned `complete: true`. Feature inspection also reads mutable current files while labeling results with the cached snapshot. This mixes source generations. Either inspect immutable pinned bytes or re-attest the non-live source before accepting receipts. Findings-directory churn should remain harmless; actual source drift must be visible and require refreshed evidence.

6. **12-F4, MEDIUM — Ordinary reviewer receipts can omit the assessment dimensions and requirements.** [The reviewer schema](/home/ben/Code/CLI/openbuff/agents/reviewer/code-reviewer.ts:117) requires a dimensions object but none of its five keys; requirement coverage is optional. Gate checks examine reported blockers but do not detect omitted assessments. A matching `LOOKS_GOOD` receipt with `dimensions: {}` and no requirements passed the exported guards for a contract file that was explicitly ineligible for the lightweight tier. The runtime verdict guard also accepted it. Prompts request complete assessment, but that request is not a completeness check. Require typed dimension outcomes and coverage of an established requirement roster for ordinary reviews. Keep reduced receipts available through explicit eligibility and escalation. No frequency of model omissions is claimed here.

7. **12-F7, MEDIUM — Corrupt unresolved findings disappear without a degraded-evidence state.** [The store](/home/ben/Code/CLI/openbuff/sdk/src/services/local-harness-store.ts:320) provides corruption diagnostics and quarantines bad records. [The review bundle](/home/ben/Code/CLI/openbuff/sdk/src/tools/get-change-review-bundle.ts:882) uses `list()`, which drops those diagnostics. A real in-scope open finding appeared before its JSON was corrupted, then became `findings: []`, with no returned error or diagnostic, after quarantine. The CLI has no lost-record information to show. Return availability and corruption diagnostics for ownership, validation, and findings, and retain them across subsequent reads so quarantine cannot turn the next call into apparent clean emptiness. The existing store-level corruption test is valuable but does not cover this consumer failure.

8. **12-F8, MEDIUM — Audit coverage cannot represent a completely assessed absent capability.** [Coverage evaluation](/home/ben/Code/CLI/openbuff/sdk/src/services/audit-intelligence.ts:431) requires every feature to be verified complete with all implementation categories populated. A fixture with every inventoried file/domain declared covered and an assessed absent action remains incomplete; feature out-of-scope reasons do not change that check. The procedure then forbids synthesis. This conflates whether an audit inspected a capability with whether that capability works. Introduce separate audit-coverage, maturity, and assurance fields, including verified negative evidence. A completed audit must be able to report absent or unwired abilities while honestly leaving product readiness incomplete. This complements the root’s opposite counterexample, where an unimplemented feature is promoted to complete.

**Capability maturity and useful strengths**

Structural discovery is usable as a local metadata inventory. Native handlers delegate to real SDK implementations, and the wrappers expose useful commands, manifests, public-API candidates, tests, and language/framework signals. Snapshot stability excludes live journal and findings churn. However, the root’s native prefix-hash and active `cli/release` exclusion probes mean this snapshot is not an exact complete-source guarantee. Supplemental omitted-source evidence remains context; omitted paths are excluded from this shard’s structural receipt.

The durable audit sink is usable at the inspected static and unit-test level. Runtime-owned path derivation, bounded identifiers, control-character hygiene, trimmed unique coverage lists, exclusive creation, confirmed mutation outcomes, content hashes, and exact-content collision checks provide meaningful integrity. Identical retry and changed-content collision are distinguished. Preserve this machinery. A returned structural receipt still attests declared inspection; it does not independently prove executable readiness or actual source reads.

Reviewer execution and validation are partial. Read-only reviewer grants prevent self-repair or test execution, and inherited parent orchestration is disabled. Structured verdicts, missing-coverage blockers, requirement blockers, crash handling, and receipt correction are useful controls. The tested foreign-token tolerance and optional assessment fields limit their assurance. Targeted validation correctly separates optional check evidence from gate authority and distinguishes skipped hooks from passed checks, but its content identity needs repair.

Environment and build intelligence are usable discovery aids with partial target-language depth. Workspace ownership, explicit command confidence, asynchronous bounded probes, and shared discovery reduce guessing and repeated work. Non-JavaScript commands remain inferred. The `get_affected_tests` consumer explicitly reports that its graph tier is unwired, and historical coverage impact is an empty placeholder. Tests using an injected reverse-dependency callback cannot graduate the default tool. Toolchain presence, grammar loading, generated command strings, and existing test filenames are separate observations.

Task and workspace tools offer usable plan-state and Git identity reads. They should not be advertised as a unified live task authority: `get_task` reads a durable plan session, while `inspect_workspace` returns Git metadata and no content snapshot. Review-bundle ownership/validation/finding arrays have a store reader, but this slice found no default runtime producer for validation/findings and no production construction of the exported ownership service. That is missing default wiring, with optional host integration still possible. The store’s CAS, private file modes, and corruption quarantine are useful infrastructure, not proof that those records contain current run outcomes.

The canonical tool and spawn catalogs are strong maintainability foundations. Published schemas and TypeScript mirrors derive from shared descriptors; unsupported schema mapping throws rather than silently fabricating a type. Static mode gates deny unlisted future tools. Compatibility and quarantined tools are explicitly distinguishable from shipped grants. Local template resolution validates schemas and preserves provenance classifications. These strengths support a capability catalog, but registered membership must still be separated from granted, installed, healthy, and semantically supported operations.

**Macro sufficiency, autonomy, and plan fidelity**

For a model to observe, act, control, continue, coordinate, remember, learn, govern, and connect, the body must preserve deterministic state and outcomes across those boundaries. This shard directly assesses observation, review/control evidence, governance defaults, task reads, and SDK dispatch. Parent evidence supplies the edit, provider, continuation, supervision, and memory counterexamples; those remain cross-shard context rather than independently repeated measurements here. No complete body-wide live acceptance or “best possible” ranking follows from this slice.

Configurable generators, custom tools, project-local agents, explicit modes, and specialist contracts give the model substantial strategic freedom. The bundled base2 gate nevertheless embeds a particular hooks/reviewer/repair workflow. Preserve its useful policy guarantees while moving lifecycle, source identities, cancellation, budgets, approvals, and outcome truth into canonical host contracts that any strategy can consume. Do not confuse a prescribed workflow with the model’s intelligence, or remove human controls merely to reduce friction. Existing opt-outs and trust choices have different purposes and need individual graduation evidence.

Learning remains unknown at this shard’s closed-loop assurance level. A verified-knowledge helper and decision records store evidence; they do not themselves demonstrate held-out improvement, a deployed promotion loop, or reliable future injection. The memory/evaluation shards own those mechanisms. Cross-language cooperation is partial: discovery and ecosystem commands exist, while graph-backed targeting and immutable cross-component interface evidence still need real consumer paths.

The current design documents handle assurance more honestly than a blanket completion claim: source-supported scenarios, executed fixtures, compiled PTY checks, unverified human/emulator acceptance, and missing original baselines are explicitly separated. Retain those qualifications. Public harness prose should be corrected for fingerprint equality, hook trust/default timeouts, and workspace snapshot behavior. README’s comparative multi-agent benefit is a product claim, not a measured result in this review.

Use the existing 120-task inventory as historical disposition context. Latest D29–D56 amendments take precedence over early choices: retain open capability tiers, explicit trusted-module replay rather than heap snapshots, TS/Rust with conditional offline Python, current platform isolation choices, one native authority, and ecosystem tools. Repair source/result semantics in TS now; Rust earns kernel enforcement, OS ownership, and fencing work through measured integration. A new authored language requires a concrete capability case. The replacement ready queue should start with the probes above, then wire missing evidence consumers, prove cross-language contract tasks, and demonstrate a learning loop. Each work package needs producer/consumer anchors, positive and adversarial acceptance, exact evidence artifacts, dependencies, and a stop/defer rule.

**Coverage and limits**

All eight domains were considered. Security covers inferred execution trust and artifact input hygiene; correctness covers identity and assessment gates; state mutation covers cache drift, quarantine, and receipt identity; error handling covers lost corruption diagnostics and stale refusal; performance covers bounded probes/hashes and synchronous native audit traversal without fabricated latency; dependency hygiene covers canonical generation and the pinned Bun contract without vulnerability claims; test coverage distinguishes helper fixtures from production consumers; API contracts cover nested snapshots, optional assessments, and documentation drift.

This is bounded inspection of the assigned slice, with selected adjacent consumers and tests. Native Codex-exposed audit tools were unavailable; repository functions were used directly for the recorded local probes. Whole-CLI behavior, installed native paths, foreign toolchains, network policy, learning outcomes, and the other shards’ internals are not certified here.
