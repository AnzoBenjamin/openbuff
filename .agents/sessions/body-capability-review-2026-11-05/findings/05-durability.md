Openbuff has useful durable storage and recovery controls, but it does not yet provide dependable continuation of one executable session across crashes, detached children, and ACP reconnections. The strongest parts are the SQLite reader/writer, atomic checkpoint queue, merged task-memory records, and explicit snapshot preview. The central gaps are where these pieces meet their consumers: main resume changes journal identity, model-selected tools bypass the programmatic replay boundary, a parent closes a live child's journal, and ACP reloads projections while discarding the core conversation.

The findings below separate observed behavior from consequences inferred from the consumer trace. Confidence is high for the cited implementation facts; no killed live provider run was exercised.

1. **05-F1 — HIGH: main checkpoint resume loses its journal identity.** The TUI restores checkpoint state and sets `resumeInterruptedTurn` ([use-send-message.ts:735](/home/ben/Code/CLI/openbuff/cli/src/hooks/use-send-message.ts:735)). The loop nevertheless calls `startAgentRun` unless `pinnedRunId` was supplied, then overwrites the restored ID ([run-agent-step.ts:1963](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/run-agent-step.ts:1963)). Production mints a fresh UUID. DI observed completed-result lookup under that new ID while the old result remained present. If a generator re-derives an effect completed after the last checkpoint, the replay guard cannot find its receipt. Pin interrupted main identity and define a distinct fresh-turn transition. Acceptance must restart from an older checkpoint and prove an already-completed effect counter stays one.

2. **05-F2 — HIGH: P2 tool replay does not cover model dispatch or reconcile uncertain effects.** Model calls use `executeToolCall` directly ([stream-parser.ts:706](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/tools/stream-parser.ts:706)); journal intent/result pairs and lookup are in the programmatic wrapper. DI executed a model read and retained its history while its journal held only LLM request/response and a step boundary. The production SDK consumer also passes no P2 journal into `handleToolCall`; optional Memory V2 observations run after the handler. Filesystem broker receipts remain a separate strength. A crash after a shell/custom/MCP effect but before durable acknowledgement cannot be safely resolved by “no result, execute live.” Move boundaries to shared dispatch and expose unknown outcomes. Probe a helper killed after an external-effect counter advances, across each dispatch family.

3. **05-F3 — HIGH: detached work stops journaling at parent completion.** TUI/headless cleanup closes their journal after the parent promise settles. Children inherit the same handles; close makes later appends no-ops ([run-journal.ts:1418](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/util/run-journal.ts:1418)). The real background re-drive is detached too. This avoids closed-database exceptions but loses subsequent requests/results/terminal tails. A later restart can recover stale history or keep an unsettled respawn marker. Journal lifetime must follow the session and live children, or each child needs its own owned connection. Hold a child until after real CLI cleanup, then settle it and reopen disk storage; both child result and parent settlement must remain present.

4. **05-F4 — HIGH: ACP reload is not conversation continuation.** Every bridge prompt calls `client.run` without `previousRun`, checkpoints or P2 journal handles, and discards the returned state ([bridge.ts:754](/home/ben/Code/CLI/openbuff/sdk/src/serve/bridge.ts:754)). ACP stores receipt/gate/capability projections rather than the transcript/main state. Its optional history loader is not supplied by `runServe`. DI confirmed that a second prompt lacks prior state, and a nonexistent session loads successfully with `{}`; the derived loader ignores a false restore result. Advertising resume/replay merely from a configured journal directory overstates this path. Persist per-session executable state, wire its prior state/history/checkpoints, and distinguish missing/corrupt sessions. A restart test must preserve a first-turn constraint into the second core prompt.

5. **05-F5 — HIGH: loading a running ACP ID loses control of its original turn.** Each socket owns a fresh agent/session map. Loading on a new connection creates a null controller, while prompt exclusion and cancel inspect only that map ([acp-agent.ts:886](/home/ben/Code/CLI/openbuff/sdk/src/services/acp/acp-agent.ts:886)). With two real connection-level agents sharing a store, DI showed the loaded client's cancel missed the first controller and a second prompt was admitted before the first settled. The socket detach test currently detaches after completion. The inferred risk is concurrent work and an inaccessible original run after intended detach/reconnect. A service-wide session owner must preserve one turn and controller while connection sinks change. Test live socket detach, load, cancel and prompt exclusion explicitly.

6. **05-F6 — MEDIUM: a killed socket holder strands startup.** The service creates an anonymous `.lock` with exclusive open and refuses any existing lock before stale-socket handling ([socket-listener.ts:129](/home/ben/Code/CLI/openbuff/sdk/src/serve/socket-listener.ts:129)). There is no owner record or dead-holder reconciliation. DI reproduced refusal with the same anonymous residue; a real SIGKILL cannot execute graceful release. Use an ownership-verified recoverable lock and distinct live-owner/stale-owner outcomes. Acceptance should kill a temporary service after acquiring ownership, restart at the identical path, and also prove another live owner is never displaced.

7. **05-F7 — MEDIUM: live writer leases expire without renewal.** Spawn/inline paths acquire and release leases, but no production caller invokes the extension helper. The next acquisition sweeps the thirty-minute TTL even while child work can run indefinitely ([workspace-path-leases.ts:45](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/util/workspace-path-leases.ts:45)). Shortened-TTL DI admitted an overlapping owner while the first durable record still said active. Same-process scope protection therefore ends before a long child does. Tie renewal and release to supervised liveness, with fencing on replacement ownership. Keep a child live across several injected TTLs and verify overlap remains excluded until settlement.

8. **05-F8 — MEDIUM: advisory workflow state updates are unwired by a member-name mismatch.** Runtime generator parameters provide `transitionBase2Gate` ([run-programmatic-step.ts:476](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/run-programmatic-step.ts:476)); shipped base2 only reads `transitionBase2GateSafe` ([base2.ts:8536](/home/ben/Code/CLI/openbuff/agents/base2/base2.ts:8536)). Its type guard skips the workflow-state branch. The safe helper's unit tests do not catch that injection gap. This affects advisory persistence/telemetry, not the authoritative finalization verdict reviewed by pair03. Align the typed injection contract and test the real runtime-to-shipped-generator path, including an illegal transition that produces a durable structured error.

9. **05-F9 — MEDIUM: snapshot publication can lose a reported recovery point.** Each producer reads the private ref parent separately and publishes with unconditional `update-ref` ([turn-snapshots.ts:461](/home/ben/Code/CLI/openbuff/cli/src/utils/turn-snapshots.ts:461)). Bisection guards do not serialize other snapshot producers; end-turn capture is fire-and-forget. Barrier-controlled DI made both producers return created with sibling commits, so only the last can remain in the listed chain. A slow capture can also overlap later edits. Serialize capture/publication per repository and compare the expected old tip. Acceptance needs two concurrent temporary producers and a queued fast mutation; retained chain and turn attribution must be correct.

10. **05-F10 — MEDIUM: JSON replay discards assistant text.** Runtime LLM response records contain `fullResponse` ([run-agent-step.ts:1089](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/run-agent-step.ts:1089)), while the JSON replay mapper reads only `text` or `message` ([replay-command.ts:87](/home/ben/Code/CLI/openbuff/cli/src/commands/replay-command.ts:87)). DI with the actual payload shape returned exit zero and an empty text event. Retained answers disappear from exported replay/evaluation fixtures even though the human trace can display the payload. Share a versioned response schema with explicit visible text and deliberate legacy handling. Test loop-to-replay ordering and nonempty plain assistant content without re-executing effects.

Several existing choices deserve preservation. Checkpoint bytes are captured before queued I/O, temp rename protects against partial JSON, and clear drains in-flight writes before unlink. Task-memory saves merge under locks, keep owner-only files, require adapter atomic capabilities, and preserve committed contributions from cooperative aborts. LocalHarnessStore supplies revision checks and ownership-aware locking. Background reconstruction pins the original child identity, refuses invented prompts when history/linkage is missing, and has actual loop DI tests beyond its recording fixtures.

Snapshots offer explicit preview/apply and untracked collision refusal, preserve the real index/HEAD, and have useful real-Git cancellation/restore tests. Their product contract deliberately materializes target-present tracked files and retains target-absent paths; it is not a deletion-aware rollback. Untracked content is excluded, and retention's repo-global replace-ref side effect is disclosed. These are maturity limits rather than newly invented defects. ACP redacts stored receipts and merges live state during restore. Its local token checks, safe socket directory checks and typed same-connection errors are real. The dashboard actually reads the shared journal and distinguishes absent/unavailable sources.

The “kill-9” journal fixture never kills a process and never applies its incomplete second effect before the simulated crash. Reopen tests cover graceful flush/close. Background integration tests use seeded streams, controlled dependencies and test IDs; supervised children lack the transported journal functions. The executable plan should first establish one durable session/run identity and state owner, then shared effect intent/outcome policy, followed by child-aware journal lifetime and ACP reconnect ownership. Service lock recovery, queued-write acknowledgement/atomic ACP rewrite, and lease supervision fit behind that owner. The helper-name and replay-schema repairs are small independent TypeScript work packages; snapshot publication needs the existing repository mutation/lock authority. Each package should finish with its concrete restart/cancel/failure probe and an observable receipt, not a successful log-only adapter count. Keep lane creation and a daemon expansion deferred until those guarantees pass. There is no evidence here that a language port fixes these consumer errors: keep one TypeScript authority now and require versioned identity, cancellation and effect receipts before adding a foreign service boundary.
