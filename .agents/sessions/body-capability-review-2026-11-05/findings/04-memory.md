**04 — Memory, compaction, recall, and the learning bridge**

Openbuff has substantial memory machinery, but its production handoffs prevent the strongest retention and learning claims. The default CLI currently selects `sqlite-v2-opt-in`; storage, native capture, turn preparation and protected prompt injection are connected. A real SQLite fixture nevertheless rejects the terminal lifecycle batch, excludes previous-task observations from the next prepared turn, discards explicit decision meaning and returns a tombstone instead of a retained original result. These failures need repairs in the existing TypeScript paths before additional ML infrastructure can contribute.

The companion [structured report](/home/ben/Code/CLI/openbuff/.agents/sessions/body-capability-review-2026-11-05/findings/04-memory.json) contains source lines, eight-domain assessments, precise reading ranges and executable work packages. The [fixture](/home/ben/Code/CLI/openbuff/.agents/sessions/body-capability-review-2026-11-05/evidence/04-memory-fixture.ts.txt) and [results](/home/ben/Code/CLI/openbuff/.agents/sessions/body-capability-review-2026-11-05/evidence/04-memory-fixture-result.json) use disposable public data, native helpers and real SQLite close/reopen. Eight findings have bounded integration evidence; the authority mismatch has a static request-construction trace. None is evidence of live model performance.

|---|---|---|---|
| Context compaction | usable | Runtime governor → shipped programmatic pruner/`set_messages` → request rebuild; source trace and actual-generator retention tests inspected | Bounded extraction, not lossless history; helper tests do not drive a full resumed run |

Maturity describes the bounded behavior that exists; assurance describes what this review actually established. A passing source-level test or a documented helper does not establish the downstream consumer.

**04-F1 — HIGH: terminal memory events collide with startup events.** The startup `task.transitioned` and terminal `task.transitioned` both use `sourceIndex: 1` with the same project, session and user-input identity ([coordinator.ts](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/coordinator.ts:1130), [terminal construction](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/coordinator.ts:2145)). The [identity factory](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/event-factory.ts:27) does not include status or time. SQLite correctly refuses the second payload as a conflicting event ID and rolls back the entire terminal batch.

The fixture used different timestamps and still produced identical IDs for active/completed transitions. State remained `finishing`; restored preparation replayed the same rejected batch, reported `lifecycle-append-failed` and installed no V2 context. Failure and cancellation statuses use the same identity scheme. Give lifecycle phases distinct replay-stable identities, preserve payload equality checks, and provide reconciliation for already parked checkpoints. Acceptance must prepare, capture, finish, reopen, restore and start another turn for every terminal status, with repeated terminal replay remaining idempotent.

**04-F2 — HIGH: the next turn cannot retrieve ordinary previous-task memory.** Normal preparation derives a new task ID and passes it as an exact query filter ([coordinator.ts](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/coordinator.ts:1173)). SQLite then rejects every candidate whose observation belongs to another task ([repository predicate](/home/ben/Code/CLI/openbuff/cli/src/services/memory-v2/bun-sqlite-memory-repository.ts:5235)). The fixture's next prepared turn received zero observations with `degradation: none`; querying that same reopened database without the task filter returned the stored discovery.

The [cold-start test](/home/ben/Code/CLI/openbuff/cli/src/services/memory-v2/__tests__/two-session-cold-start.test.ts:148) bypasses this defect by querying the repository directly without a task ID. A valid empty correlated V2 context also suppresses V1 compilation. Separate current-task correlation/ranking from explicit exact-task filtering and retrieve applicable project knowledge independently. Acceptance must learn in A and inject the relevant observation in B after reopen, without knowing A's internal task ID. Home/project knowledge files and skills are separate working paths; configured semantic expansion can append advisory cross-task matches. This finding does not mean all memory is absent.

**04-F3 — HIGH: explicit decisions lose their meaning in canonical V2 capture.** The [native handler](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/tools/handlers/tool/record-decision.ts:243) returns decision text, evidence paths and optional excerpt, and stores the real text in V1. The coordinator reads that text to derive claim identity, but writes a generic tool/path/count summary and digest ([capture payload](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/coordinator.ts:1623)). Evidence excerpts are likewise synthetic metadata. The fixture's V1 record retained its decision sentinel; the V2 event retained neither the rationale nor the supplied excerpt.

Persist bounded explicit decision/rationale text and approved excerpts as untrusted canonical evidence. Keep generic tool capture minimal. A native-handler → capture → SQLite export/query → compiler → reopen probe must preserve the meaning independently of V1 import, including dedup and supersession. Existing capture tests assert kind and selectors while missing this requirement. V1/transcript copies mitigate total loss, but do not make V2 independently useful knowledge.

**04-F4 — HIGH: a later snapshot shadows original-body recall.** Eviction archives a full result, then replaces its transcript entry with a pointer. The next pre-compaction capture stores that pointer under the same call ID. [Exact-ID recall](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/util/context-archive.ts:525) chooses the newest matching copy across all archive kinds. The [registered tool](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/tools/handlers/tool/recall-context.ts:45) follows that path whenever a call ID is supplied.

The fixture used the actual evictor's default six-step threshold, three pre-compaction captures and SQLite reopen. Original recall worked before capture; afterward it returned a tombstone although the original remained retained. Keyword recall remains a possible workaround. Prefer original eviction payloads or record body completeness and skip pointer-only/slimmed copies. Acceptance must recover the original body and provenance after repeated compaction and restart. Existing duplicate-ID tests use hand-built eviction snapshots and therefore never create this production-shaped collision.

**04-F5 — MEDIUM: the compiler replaces ranked order with JSON order.** SQLite establishes freshness/usefulness/relevance order and appends semantic matches after the lexical prefix. [Compilation](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/util/memory-v2-context.ts:277) sorts discoveries by JSON content and clips the resulting block to 12,000 characters. Nine schema-valid fixture items with the highest-ranked item first produced a full-budget prompt containing a low-ranked item and omitting the highest-ranked sentinel.

Preserve ranked category order, canonicalize only unordered nested metadata, and budget selected complete items by priority. Return the exact emitted observation set for downstream accounting. Acceptance must retain the high-ranked z-ID item ahead of long low-ranked a-ID entries and keep semantic advisory additions behind lexical matches. Raising the budget only masks the selection error. Current tests explicitly treat ranked category arrays as unordered, so their byte-identity assertion protects the wrong contract.

**04-F6 — MEDIUM: verifying a successful procedure deactivates it.** The [lifecycle evaluator](/home/ben/Code/CLI/openbuff/cli/src/services/memory-v2/playbook-lifecycle.ts:142) marks an effective active rule `verified`; the real operator apply path persists that status. Yet [runtime loading](/home/ben/Code/CLI/openbuff/cli/src/services/memory-v2/bun-sqlite-memory-repository.ts:1601), prompt compilation and the deterministic gate all accept only `active`.

The fixture recorded qualifying counter outcomes, applied the actual status transition, and observed the loaded rule disappear; compiling the verified row returned zero characters. Model verification quality independently from activation, or consistently treat verified rules as active. Acceptance must verify, reopen and still load/enforce the rule, while retirement and expiry still remove it. The current prompt test explicitly expects verified rows to disappear. The observed defect concerns consumer semantics; the fixture did not establish that a model generated those effectiveness counters.

**04-F7 — MEDIUM: negative feedback is manufactured from unrelated reads.** [Usage correlation](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/usage-observer.ts:119) treats any full read as grounds to mark every other retrieved observation `ignored/reread-despite`. It does not require a reread of that observation's source. The fixture served a known chunk and supplied one full-read receipt with no covered identity; correlation returned an ignored signal.

Those counters feed usefulness before lexical ordering, so the error can change future behavior. Unshown items lost to compiler clipping can also be misclassified. Correlate actual emitted records against attempted/covered source identities; distinguish necessary freshness refresh from rejection and preserve unknown where use is unobserved. Acceptance must read unrelated B without penalizing A, then explicitly reread A and produce the intended signal. Read avoidance is an efficiency metric, not proof of better task outcomes.

**04-F8 — MEDIUM: declared procedure scope is not enforced.** The [public schema](/home/ben/Code/CLI/openbuff/common/src/types/memory-playbook.ts:33) accepts repository, glob and agent-type scope, and authoring stores it. Runtime loading filters only workspace/status/expiry; [gating](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/memory/playbook-gate.ts:288) checks trigger and evidence without scope. The tool-executor consumer supplies no applicability context. The fixture obtained a verdict from a rule restricted to another project, Rust globs and a Rust specialist.

Use one applicability evaluator before both trusted instruction selection and gating. Supply project, current agent and affected paths; explicitly reject or report unsupported restrictions. Acceptance must vary each restriction independently and preserve existing behavior only inside scope. This concerns misapplied operator procedures and unnecessary warnings/blocks, not a demonstrated OS sandbox escape. It is especially relevant to lessons whose usefulness differs between target languages.

**04-F9 — MEDIUM: degraded authority and actual injection disagree.** The [SDK contract](/home/ben/Code/CLI/openbuff/sdk/src/services/memory-v2/types.ts:32) says unavailable opt-in V2 injects nothing and does not silently fall back. Degradation clears V2 context but leaves `active=sqlite-v2-opt-in` and `fallbackOccurred=false`. [Request construction](/home/ben/Code/CLI/openbuff/packages/agent-runtime/src/run-agent-step.ts:2534) instead compiles V1 whenever no correlated V2 context exists.

With a V1 compatibility record present, open/query/lifecycle failure therefore emits V1 while reporting V2 without fallback. Choose one deliberate policy and align metadata, documentation and captured request messages. Acceptance must exercise unavailable/invalid/throwing V2 with V1 present/absent and compare the emitted source to authority telemetry. This ninth finding is a direct static Boolean-path trace; no provider-facing fixture was run.

Useful machinery should be retained. Compaction keeps a protected operational floor, revokes stale read authorization and uses revision-CAS transcript/task-memory replacement. The default shipped pruner is a programmatic extractor yielding `set_messages`, despite comments elsewhere describing an expensive LLM pass. V1 has checksum inspection, project-contained streaming evidence reconciliation, merged serialized saves and owner-only atomic persistence. SQLite project binding and idempotent payload equality are sound safeguards; the coordinator must respect them. Configured semantic recall validates vectors, bounds new embedding work, fences abandoned writes and preserves lexical fallback at the repository boundary.

The learning bridge is partial in additional ways. New operator proposals are `active/inject-only`, but the gate skips inject-only rows, so there is no natural firing producer for their eight-fire promotion threshold; lifecycle tests seed counters manually. Only `toolSucceeded` procedural evidence is implemented. Written `LESSONS.md` and updated skills are inspectable, useful model-directed workflows, and fresh sessions rediscover skills. They do not provide a runtime-vetted held-out promotion loop. Optional background consolidation is a separate off-by-default summary layer; oversized tool lines can be skipped by its prompt budget while coverage still credits the entire snapshot.

Retention bounds are honest limits, not full artifact durability. Archives hold eight semantic/mechanical plus sixteen eviction snapshots, 200 messages per snapshot and 4k/64k text caps per part. Runtime recall sees the hydrated array; the optional durable archive search API has no consumer in this trace. Larger original outputs need immutable artifact references and range reads. Media and multiple parts also need an aggregate-byte envelope, with measured RSS/latency before a storage rewrite. Fresh SDK hosts must preserve returned state or provide a persistence consumer; CLI archive wiring does not automatically prove every transport's restart behavior.

The ready queue should first repair terminal identity/reconciliation, then cross-turn retrieval, explicit decision meaning and truthful authority. Next repair archive selection and final ranking, followed by procedure activation, applicability and trustworthy usage receipts. Only then run paired cold/warm held-out tasks through canonical CLI/SDK behavior, repeated compaction and an actual disposable process restart. Preserve V1 compatibility until lossless migration gates pass.

Target-language cooperation can already be tested with TypeScript/Python/Rust fixture contracts and source-bound evidence. Memory's present path/selector DTOs are broadly language neutral, while ASCII-oriented lexical tokens and generic shell/prose procedures do not prove semantic contract recall. A new implementation language should unlock a measured capability, behind versioned schemas, agreed byte/position encodings, cancellation and typed effect/outcome receipts. Python statistics cannot repair missing facts at the model's next decision.

All eight domains were considered: security and applicability; correctness; transactional/state ownership; failure/retry observability; resource budgets; Bun/Node dependency boundaries; test adequacy; and public schema/injection contracts. The structured receipt covers 61 current-inventory files with sampled ranges, including every picker-selected section. Large repositories/pruner code remain sampled. No live model, killed CLI resume, attach transport, release artifact, multi-process archive race, non-Linux platform, performance benchmark or held-out learning comparison was exercised. Existing retention S6 simulates read savings from hand-built DTOs with zero model calls; repeated-compaction tests drive the real generator but bypass tool dispatch and persistence. Those are valuable lower-level checks whose limits explain why the production defects survived.
