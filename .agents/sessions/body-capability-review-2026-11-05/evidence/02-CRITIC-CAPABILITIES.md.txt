## Reading the catalog

The body supplies observations, deterministic actions, lifecycle, evidence and human controls; the model supplies reasoning and chooses actions. A strategy prompt or tool name does not establish a working capability. Conversely, a narrow callable component can be useful even while its larger workflow remains partial.

Maturity is independent of assurance. Usable means a declared narrow path reaches its consumer. Partial means reachable behavior has material gaps or incomplete coverage. Unwired means implementation exists without its required production consumer. Absent means the reviewed path lacks the ability. Unknown means available evidence cannot establish it. Composite rows preserve these distinctions instead of averaging an absent frontier into a working core.

S means static trace, including inspected tests. U means executed unit/helper evidence. I means bounded offline integration, sometimes with injected providers, peers, Git or judges. These letters do not certify every branch in a composite row. No row has live provider/model-task quality assurance. Linux subprocess and standalone Rust observations are real local execution; fake CDP, synthetic vectors and injected judge scores are labeled accordingly. Full installed/platform certification remains separate.

Each trace abbreviates entrypoint→implementation→real consumer. Complete test/doc references and failure, loading, empty, cancellation, retry and permission states are in the mapped JSON records. Graduation must test those relevant states through the actual consumer, including truthful unsupported/degraded behavior. An unavailable analyzer is not a clean diagnostic result; a failed action can be followed by a successfully recovered task without changing the earlier receipt.

The best-version column states acceptance criteria for a declared workload. Correctness, byte preservation, source identity, ownership and outcome invariants can be fixed now. Claims about improved task success, interruptions, latency/cost/memory or learning require comparable baselines, repeated trials and explicit uncertainty.

Every row below retains generic text/shell work where applicable; binary operations follow their specific tool contracts. The inventory is twelve profile IDs, fifteen grammar variants across fourteen named source languages, eleven stdio LSP launch specs and fourteen executable probes. These counts describe available mechanisms. C19–22 and the source report record failures, unsupported cells and setup conditions. No real multi-language LSP/compiler task or external SCIP extraction was executed in this review.

Authored-body cooperation has a different gate. TypeScript currently owns the runtime; Rust's standalone exec supplies real Linux filesystem enforcement. The native host adapter is unwired and its framing differs from generic supervision. A TS→Rust fixture must prove negotiated request/output, effective policy, ownership and cancellation without depending on an authored Python component. Optional offline Python statistics/oracles can consume immutable evaluation receipts when they provide a measured advantage. Operating on a Python target project is independent of that choice.

Consume established parsers, LSP/SCIP indexers, compilers and native UI libraries before considering ports. Their implementation languages do not count as authored Openbuff languages. Language expansion should unlock a specific capability, preserve one effect/session authority and carry versions, encodings, typed failures and artifact/outcome identities. No language-variety rewrite or live heap snapshot is a graduation criterion.

## Reusable foundations and macro limits

Preserve canonical tool/schema/spawn generation, strict BYOK routes, delivery-based tool retry safety, authenticated complete-read grants, pure edit preflight, conditional staging, atomic checkpoint queues, V1 merge/CAS, SQLite binding/payload equality, lexical graph modes, source-aware watchers, immutable grammar provenance, original custom-tool schemas, scoped approvals and owned browser/3D attempt files. Each removes work the model would otherwise have to guess. Their remaining adapter/consumer gaps are the highest-return repairs in the audit families.

Long-running interactive work, post-crash continuation, automatic cross-component validation, installed native host effects, declarative/untrusted plugins and desktop/voice operation bundles remain partial, unwired or absent. Their inclusion is a capability inventory, not a commitment to implement every frontier. A concrete workload and cost/quality envelope determine when to proceed.

Learning is particularly dependent on preceding truth: relevant facts must reach the next decision, actions/runs/tasks must retain independent outcomes, experiments must preserve eligible paid/failed attempts, and measured proposals must actually change a consumer. Current lessons, counters, recommendations and consolidation are reusable pieces. No held-out adopted improvement was established.

The review covered all assigned top-level subsystems with bounded source/test/doc windows, not every line. Recovered receipts enumerate 555 inventory files and 147,555 unique sampled lines including three supplemental context files. The historical 147,721-line claim exceeds the recovered total by 166 unsupported lines. The original full-file hash map is missing; [SOURCE-STABILITY.md](SOURCE-STABILITY.md) records the narrower comparison supported by surviving captured windows, and fresh current hashes do not certify historical full-file equality. Live providers, actual browser/Blender use, full packed SDK/binary tasks, non-Linux platforms and killed live CLI continuation remain outside demonstrated assurance. [COVERAGE.md](COVERAGE.md), [REVIEW-VALIDATION.json](REVIEW-VALIDATION.json) and individual reports retain those limits.
