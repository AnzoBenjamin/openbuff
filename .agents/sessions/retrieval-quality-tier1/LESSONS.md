# LESSONS — Retrieval & Memory Quality Tier 1

- Child `editor` agents failed repeatedly in this runtime: a parallel wave died with a shared harness error ("No output generated"), and a solo retry reported `edit_transaction_uncommitted` with phantom "changed files" claims but zero mutation receipts and no git diff. The parent's own `edit_transaction` worked throughout. Rule: verify child editor claims via mutation receipts + `git status` before trusting them; fall back to direct parent edits when the child edit path is broken.
- `parseFile` omits the `identifier` key entirely when a source yields zero identifier captures; `new Set(undefined)` tolerated it but `for...of undefined` throws. Any new iteration over capture arrays needs a `?? []` coalesce (caused 6 test regressions, fixed by one guard).
- Content-hash dedup on evidence must NOT apply to machine-derived read/edit kinds: they already dedupe by stable per-path id and are distinguished by freshnessHash — collapsing them destroys legitimate fresh re-reads (broke the SDK prune-resurrection test and retention S5 until read/edit were exempted).
- A boolean second-hop gate must be polarity-checked for the empty-tokens case: `tokens.length > 0 && some(...)` silently disables expansion for neighbors-mode queries seeded by an explicit file (pinned by 'supports neighbors mode from an explicit file').
- The retrieval-quality corpus at k=3 is insensitive to graph-expansion changes by construction (path-closed corpus, lexical channel only); record that expectation so a flat metric line is not mistaken for a no-op change.
- Baselines first paid off: the stash-based at-HEAD test run separated the 1 pre-existing WASM-coverage failure from the 6 regressions my edits caused, avoiding misattribution.
- The memory-retention S5 noise-ratio metric measures the compiled-context contract, not the durable store; durable-store behavior needed its own dedicated test ('session-scoped read evidence stays ephemeral across saves').
