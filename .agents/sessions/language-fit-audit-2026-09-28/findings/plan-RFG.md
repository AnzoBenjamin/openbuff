## [HIGH] security — .agents/sessions/polyglot-roadmap-v2/PLAN.md:190 — P9-T5 WASM component plugins: wasmtime (Rust, separate process role) is BEST; jco in-process REJECT for untrusted guests
- **Risk:** The plan leaves 'wasmtime (sidecar) / jco' open. jco transpiles a component into JS glue plus core wasm that runs inside Bun's JSC wasm engine, in the same address space as provider keys, cap.v3 HMAC keys and the agent loop. Capability grants would then be enforced by generated JS glue. JSC gives no fuel or epoch interruption and no per-instance memory accounting beyond the wasm memory max, and WASI p2 on JS depends on preview2-shim. A buggy host binding in-process equals a full compromise.
- **Fix:** Use wasmtime (component model plus WASI p2, fuel or epoch interruption, ResourceLimiter, wasmtime-wasi with explicit preopens and no ambient network) in a `plugin-host` role of the single Rust multi-call binary (see the topology finding), supervised by X-5 and speaking JSON-RPC. Grants are declared in the plugin manifest and checked host-side. Guests: Rust (cargo-component), JS/TS (componentize-js, where jco is fine as a build-time tool only), Python (componentize-py), Go (TinyGo). Unlocks now: untrusted tool, hook and agent-step plugins with CPU and memory caps and no FS or network unless granted. Unlocks later: the same WIT world hosts the P9-T4 untrusted agent path if QuickJS runs as a component. Cost: M-L (3-5 wk) plus the wasmtime binary size (~15-25MB, needs verification).
- **Evidence:** PLAN.md:190; SPEC Principle 3(c); rust/Cargo.toml:1-9 (no deps yet); SPEC acceptance criteria require a security-reviewer pass for P9 isolation. Confidence: medium-high. Needs web verification: wasmtime component-model and WASI p2 stability, current jco WASI p2 support, and wasmtime binary size in a combined binary.

## [HIGH] security — rust/README.md:9 — PORTFOLIO: Rust topology — ONE multi-call binary, THREE-plus process roles (daemon / shim / infer / plugin-host), not one daemon
- **Risk:** About 20 Rust capabilities have conflicting runtime requirements. (a) Daemon state (index, watcher, broker, journal, leases, jobd, PTY, memory store, socket auth, scheduler, tokenizers, git reads) wants one long-lived single writer. (b) The sandbox shim must apply landlock/seccomp/namespaces to itself before execve of the child. If it lived inside the daemon it would either confine the daemon or need fork-from-multithreaded-tokio (unsafe after fork). It should also be minimal for audit, and running it per command limits blast radius. (c) Inference, STT/TTS and ort ML take GBs of memory and GPU drivers and crash in C++ code, and D7 already forbids co-locating them with anything critical. (d) wasmtime plugins run untrusted code and need their own crash domain. The rust/README plans separate crates, shim, jobd, index, lanes, pty and infer, as standalone binaries. Six release artifacts × 5+ targets multiplies CI, signing and download cost (charter rule 3 wants O(1)).
- **Fix:** One cargo workspace with library crates (core-proto, store, index, sandbox, pty, infer, plugin) linked into ONE busybox-style binary, `openbuff-native <role>`. Roles: `daemon` (tokio; absorbs jobd, index, lanes, pty, broker, journal, leases, memory, scheduler, socket listener, tokenizer RPC, LSP mux per D42), `exec` (single-threaded, no tokio; parse bash AST → confine → execve; spawned per command by the daemon or directly by TS before the daemon exists), `infer` (llama/mistral.rs, whisper-rs, ort; optional GPU feature builds), and `plugin-host` (wasmtime). Merge jobd into the daemon, as P6-T5 already implies. The same artifact means one checksum, one signature and one download. Process separation keeps D7 crash isolation and shim minimality. Offer infer as a separately downloadable variant only if GPU builds bloat the base binary. Unlocks now: the shim ships first as `exec` with zero daemon dependency. Unlocks later: each new capability is a crate and a role, never a new artifact.
- **Evidence:** rust/README.md:9-11 (six planned sidecars, standalone binaries), :27-33 (charter O(1) toolchain, publish on first consumer); rust/Cargo.toml:1-9 (single workspace ready); SPEC D1, D7; PLAN P5-T2 'absorbed into P6-T5'; cb-sdk-tools terminal-exec HIGH (pre-exec confinement), cb-sdk-services broker HIGH (single-writer), cb-code-intel orchestration HIGH (daemon shared across lanes). Cost: none extra, since it's a packaging decision. Confidence: medium-high. Needs web verification: landlock/seccomp restrictions on applying rules in a multithreaded process (landlock restrict_self applies per thread, and TSYNC is only in newer kernels).
