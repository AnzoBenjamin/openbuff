## [HIGH] security — agents/base2/gate-reviewer.ts:153 — Reviewer attestation is a per-field splice: a quoted example entry can supply the fingerprint and reviewed-file coverage a real review never attested
- **Risk:** resolveReviewerAttestation composes ONE attestation PER FIELD across all schemaVersion-carrying entries: reviewedFiles is the union of every shaped entry, and snapshotFingerprint falls back to any entry reporting an attestable v3 value when none reports expectedFingerprint. Combined with the fingerprint-drift tolerance in collectReviewerAttestationIssues (a mismatch is a hard blocker only when a file-coverage gap also exists), a reviewer that quotes the documented example receipt (reviewedFiles: ["src/a.ts"] plus a well-formed v3 fingerprint) next to a real entry that attested nothing gets full coverage credit for any pending file named src/a.ts and an attestable fingerprint, so the gate finalizes over file content the review never read. The module's own docblock admits 'a quoted example whose reviewedFiles path COLLIDES with a real pending path credits coverage the real entry never attested'. This breaks the gate's core guarantee ('every pending file was reviewed') reachable with a merely sloppy/quoting reviewer, not a lying one.
- **Fix:** Resolve the attestation from exactly ONE entry: require a single schemaVersion-carrying entry to carry the verdict, the expected snapshotFingerprint, and a reviewedFiles set covering every non-deleted pending file; reject (fail closed) when coverage would need files from a non-attesting entry or when the fingerprint comes from a different entry than the verdict. Keep the deletions-only empty-reviewedFiles case explicit. Update the RF-1-17fea4a5 pins in agents/__tests__/gate-reviewer.test.ts to assert rejection instead of credit.
- **Evidence:** gate-reviewer.ts:153 resolveReviewerAttestation; its docblock 'ACCEPTED LOOSENING (pinned in agents/__tests__/gate-reviewer.test.ts): ... a quoted example whose reviewedFiles path COLLIDES with a real pending path ... credits coverage the real entry never attested'; the union is built at 'for (const entry of shaped) { for (const file of entry.reviewedFiles ?? - **Risk:** isParentOwnedOrOutOfScopeRequirement decides whether a missing/uncertain requirementCoverage row blocks the gate by regex-matching the requirement text (and, for ownership cues, reviewer-supplied evidence strings). ## [MEDIUM] correctness — agents/base2/gate-repair.ts:76 — Failure parser mis-reads Windows drive-letter and parenthesized paths ('C', NaN line/col) and collides them in the dedupe key
- **Risk:** The eslint/gcc regex stops at the FIRST colon, so a Windows diagnostic 'C:\src\foo.ts:10:5: msg' parses as file 'C' with line parseInt('\src\foo.ts') = NaN and column NaN; the tsc regex ([^(]+) similarly cannot handle any path containing '('. ParsedValidationFailure.line is typed number|undefined but carries NaN, buildRepairEditorPrompt renders 'NaN:NaN - [source] message' as a failing location, and the dedupe key `${p.file}:${p.line ?? 0}:${p.column ?? 0}` ('C:NaN:NaN' - NaN is not nullish so ?? 0 never fires) collapses every distinct Windows failure into one bogus entry. On Windows the automated repair editor is dispatched to a file named 'C' with no usable coordinates, wasting repair rounds and tripping the no-progress guard.
- **Fix:** Use a Windows-drive-aware path group (e.g. (?:[A-Za-z]:)?[^:]+ or a balanced-path alternative) in the unix/generic regexes, validate parseInt results (skip or re-derive on NaN), and key dedupe on the raw matched location text. Add fixtures: 'C:\src\foo.ts:10:5: msg', 'C:\src\foo.ts(12,34): error TS2322: x', 'src/(legacy)/foo.ts(12,34): error TS1: y', with a no-NaN invariant assertion.
- **Evidence:** gate-repair.ts:76 'const unixRe = /^(\S+?):(\d+):(\d+):\s*(.+)$/gm' with file=m[1].trim(), line=parseInt(m[2],10) unchecked; tscRe /^([^(]+)\((\d+),(\d+)\):/ cannot match a '('-bearing path; dedupe 'const key = `${p.file}:${p.line ?? 0}:${p.column ?? 0}`' maps all NaN-coordinate failures of file 'C' onto one key; prompt render uses 'f.line != null' which NaN passes.

## [MEDIUM] security — agents/base2/gate-repair.ts:167 — Raw hook-failure text is interpolated verbatim into the repair-editor prompt, a prompt-injection channel into an agent with file-write tools
- **Risk:** buildRepairEditorPrompt embeds parser output - messages and the whole unparsed failure body (up to 500 chars each) - directly into a prompt for the repair editor, which holds edit tools and is told to 'make the minimal targeted fix' in the named files. Hook output echoes attacker-influenceable content (compiler messages quoting source lines, lint rules quoting identifiers, test output quoting fixtures), so crafted content can inject instructions ('also rewrite X to always pass') riding along with a genuine failure.
