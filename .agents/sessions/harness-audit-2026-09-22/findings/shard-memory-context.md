## [HIGH] correctness — sdk/src/services/memory-v2/coordinator.ts:1304 — verifyCapturedPaths replays stale capture digests under the current workspace context and never clears its buffer, laundering evidence freshness
- **Risk:** verifyCapturedPaths iterates this.lastCapturedVerifies (populated at coordinator.ts:1821) which is never cleared and is shared across turns, then issues MemoryVerifyRequest 'verify' actions carrying the OLD captured observedDigest together with the CURRENT params.workspaceState revision/snapshotId. repository.verify() stamps that digest as evidence.verified for the new revision/snapshot, so buildLexicalResult.contextMatches (which requires request.workspaceRevision === freshness.workspaceRevision) promotes observations into verifiedKnowledge for a workspace snapshot where that content was never re-observed. If the file changed after capture (external edit, a later mutation not correlated to this entry), the 'verified' claim is false and the whole digest+revision honesty gate (rereadRequired suppression, cache-skip reuse decisions) is defeated. Each call also emits a fresh evidence.verified event per entry because the derived verify eventId hash includes workspaceRevision, so entries replayed across turns grow the append-only log without bound.
- **Fix:** Re-hash each selector against live disk inside verifyCapturedPaths (or capture the observedDigest only within the same workspace revision and refuse to verify when workspaceRevision changed since capture), pass a real observedAt, and clear/rotate this.lastCapturedVerifies after each successful verify batch so an entry is verified at most once per capture. Add a test that mutates a file between capture and verifyCapturedPaths and asserts the observation is NOT marked verified for the newer revision.
- **Evidence:** sdk/src/services/memory-v2/coordinator.ts:666 declares private lastCapturedVerifies (no clear site anywhere in the file). :1304 verifyCapturedPaths reads const entries = this.lastCapturedVerifies.slice(0, MAX_VERIFY_STORED) and per entry builds action { kind: 'verify', observationId, selector, observedDigest: entry.observedDigest } together with ...(params.workspaceState ? { workspaceRevision: params.workspaceState.revision, workspaceSnapshotId: params.workspaceState.snapshotId } : {}) - i.e. a digest observed during a previous capture/turn is asserted valid at the newer revision. :1821 only prepends: this.lastCapturedVerifies = [...verifyEntries, ...this.lastCapturedVerifies].slice(0, MAX_VERIFY_STORED). ## [MEDIUM] correctness — packages/agent-runtime/src/util/task-memory.ts:675 — Evidence ids truncated to 160 chars collide for long paths, and normalizeEvidence id-dedup silently drops the loser
- **Risk:** deriveToolEvidence builds stable per-path ids as boundText(`read:${path}`, 160) / boundText(`edit:${path}`, 160). boundText truncates to 160 chars with a '...[truncated]' tail, so two distinct files sharing a long common prefix (deep monorepo paths, generated paths) yield the SAME id. normalizeEvidence then dedupes by id keeping only the newest verifiedAt, so one of the two files' evidence entries is silently discarded while filesInspected/editsMade still list both paths. - **Evidence:** packages/agent-runtime/src/util/task-memory.ts:675 `id: boundText(`read:${path}`, 160)` and :707 `id: boundText(`edit:${path}`, 160)` where `path` itself is boundText(item.path, 1_000); normalizeEvidence keeps `byId.set(item.id, ...)` newest-wins per id, and boundText truncates strings longer than maxChars to maxChars with a truncation marker - identical prefixes therefore collapse to one id.
