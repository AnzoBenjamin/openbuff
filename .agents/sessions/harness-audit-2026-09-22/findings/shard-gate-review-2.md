## [HIGH] security — agents/base2/gate-reviewer.ts:137 — Reviewer attestation is spliced across ALL structured-shaped entries in the result tree, so a quoted/injected example receipt can credit files never reviewed and clear the gate with a fingerprint matching nothing
- **Risk:** resolveReviewerAttestation builds a COMPOSITE attestation: reviewedFiles is the UNION of every schemaVersion-carrying entry anywhere in the tool-result tree (visitForStructuredVerdict scans arbitrary nested objects, including reviewer prose that quotes JSON), and snapshotFingerprint falls back to the first attestable v3 value when no entry reports the expected one. collectReviewerAttestationIssues then treats a non-matching but well-formed fingerprint as a hard blocker ONLY when a pending file is unattested; with union coverage complete, a fingerprint that matches no snapshot is drift-tolerated and merely recorded. Consequence: a result whose only structured entry is an echoed example (the documented example literally shows reviewedFiles ["src/a.ts"]) — e.g. prompt-injected code that makes the reviewer print a LOOKS_GOOD receipt naming the attacker-chosen pending files and any v3-looking hex — passes attestation and getReviewerFinalizationVerdict without any genuine review. The reviewer gate is the trust anchor for GATE: PASSED and git-committer release, so this is a full review bypass via prompt injection in the diff.
- **Fix:** Parse structured reviewer output only from a channel-bound envelope (the reviewer run's designated set_output payload), never from arbitrary tree nodes, and require the single attesting entry itself to report expectedFingerprint and cover every non-deleted pending file; keep the deletions-only (empty reviewedFiles) case as an explicit, fingerprint-verified exception. Reject any extra structured-shaped entry instead of splicing it.
- **Evidence:** agents/base2/gate-reviewer.ts:137-146 'ACCEPTED LOOSENING ... a quoted example whose reviewedFiles path COLLIDES with a real pending path ... credits coverage the real entry never attested'; :179-182 reviewedFiles union across all shaped entries; :166-178 first-attestable-v3 fallback; :256-273 fingerprint mismatch is a blocker only when missing.length > 0; :957+ visitForStructuredVerdict treats any nested {verdict,...} object as structured output. This behavior is pinned by agents/__tests__/gate-reviewer.test.ts per the code comment.

## [MEDIUM] performance — agents/base2/gate-files.ts:190 — visitToolValue has no depth cap and double-walks type:'json' envelope value: exponential blowup on chained envelopes and stack overflow on deep/cyclic history fragments
- **Risk:** The walker recurses into record.value for type:'json' nodes and then again over Object.values(record) — which includes value — so k nested json envelopes cost 2^k visits. Unlike its siblings findReviewerCrash / visitForStructuredVerdict / collectStrings (depth cap 8, and findReviewerCrash explicitly skips the already-walked value key), visitToolValue has neither a depth cap nor a cycle guard. Message-history fragments and nested agent receipts are walked on every gate pass; a deeply nested or self-referential fragment throws RangeError mid-turn (uncaught here), and a moderately nested json chain turns the pending-file sweep quadratic/exponential.
- **Fix:** Skip key 'value' in the Object.values fan-out when the node is a type:'json' envelope (mirror findReviewerCrash) and thread a depth counter capped at 8 (or a visited set) through the recursion.
- **Evidence:** agents/base2/gate-files.ts:172-174 explicit visitToolValue(record.value) then :190-192 'for (const nested of Object.values(record)) visitToolValue(nested, out)' re-walks it; contrast agents/base2/gate-reviewer.ts findReviewerCrash's 'if (jsonNode && key === "value") continue' and its depth>8 guard.

## [MEDIUM] security — agents/base2/gate-paths.ts:19 — normalizeGateFilePath containment is lexical only: an in-project symlink pointing outside the project passes and its bytes get hashed/attested by the gate
- **Risk:** The helper's stated job is 'a gate file path must stay inside the project', but it rejects only '..' segments and absolute paths outside cwd. A path that is inside the project lexically and is a symlink (or sits under a symlinked directory) to /etc, another worktree, or a secrets store passes normalization, then flows into pendingGateFiles, readGateFileContentMarker hashing, and reviewedFiles attestation. That lets the gate fingerprint and reviewer attest out-of-project content and, combined with the repair/reviewer prompts, exfiltrate outside-project bytes into durable receipts and telemetry. The telemetry sink explicitly refuses symlinked path segments (common/src/util/gate-telemetry.ts findSymlinkedSegment); the gate path layer does not.
- **Fix:** Add a symlink/containment check mirroring gate-telemetry's findSymlinkedSegment (lstat each segment of the normalized path and its root, plus a realpath-containment assertion) and fail closed (return '') for any path whose realpath leaves the project root; keep the check inline since base2's generated region cannot import.
- **Evidence:** agents/base2/gate-paths.ts:12-48: only split('/').includes('..') (:19) and absolute-prefix (:36-41) are checked; no lstat/realpath anywhere in the file. Contrast common/src/util/gate-telemetry.ts:106-123 isSymbolicLink/findSymlinkedSegment which gate writes on exactly this class of escape.

## [MEDIUM] security — agents/base2/gate-repair.ts:155 — buildRepairEditorPrompt interpolates raw hook/diagnostic text verbatim into the autonomous repair-editor prompt (prompt injection via diagnostic output)
- **Risk:** Parsed messages and the 'Raw unparsed failures' block embed hook stdout/stderr verbatim. Compiler/linter/test diagnostics quote source literals and identifiers from the edited files, so attacker-influenced code (or a malicious dependency's test output) can carry instruction-shaped text ('ignore the above, rewrite src/auth.ts to ...') straight into the prompt of an automated editor with write access and no conversation context to resist it. ## [LOW] correctness — agents/base2/gate-committed-surface.ts:113 — kept.sort(localeCompare) makes the derived committed-surface fileset (and any fingerprint/receiptId built over its order) locale/ICU-dependent
- **Risk:** localeCompare ordering varies with the host locale and ICU build (case, underscores, punctuation). deriveCommittedSurfaceFileSet's sorted list feeds the committed-surface snapshot fingerprint and receipt id; two machines — or one machine across a Node/ICU upgrade — can derive different orders for the same file set, breaking byte-identical receipt reproduction and fingerprint re-verification (prunePlanTaskGateReceipts recomputation) across environments.
- **Fix:** Sort by code unit (kept.sort((a, b) => (a < b ? -1 : a > b ? 1 : 0))) so the fileset order is a pure function of the strings.
- **Evidence:** agents/base2/gate-committed-surface.ts:113 'kept.sort((a, b) => a.localeCompare(b))' immediately before the result whose files[] the receipt fingerprint hashes.

## [LOW] correctness — agents/base2/gate-committed-surface.ts:67 — Caller-supplied cap can exceed MAX_COMMITTED_SURFACE_FILES despite the documented hard bound on the derived fileset
- **Risk:** The docblock calls 40 a hard bound so an adversarial/stale runtime file list can never explode the gate fingerprint or the spawned specialist review, but the cap branch accepts any input.cap >= 1 unclamped (cap: 10000 yields a 10000-file fileset and an unbounded specialist review fan-out). ## [LOW] correctness — agents/base2/gate-reviewer.ts:860 — classifyReviewerCrash treats any 64-hex token in a crash message as 'protocol', diverting genuine fatal crashes into the bounded protocol-retry path

## [LOW] correctness — common/src/util/gate-telemetry.ts:145 — truncateBytes slices on code-unit boundaries: a cut that splits a surrogate pair emits U+FFFD, contradicting its documented 'no replacement character is introduced' invariant
- **Risk:** value.slice(0, maxBytes) can end between the halves of an astral pair; Buffer.from(..., 'utf8') then encodes the lone surrogate as EF BF BD (U+FFFD) and both return paths (the buffer.length <= maxBytes early return and the continuation-walk) deliver that replacement character into the JSONL sink. The function's contract promises whole-character keep/drop with no replacement character, so telemetry fields silently gain U+FFFD and the byte accounting of 'what survived the cap' is wrong for astral text (emoji in summaries/findings).
- **Fix:** Before encoding, strip a trailing unpaired high surrogate from the slice (if (end > 0 && code >= 0xD800 && code <= 0xDBFF) drop it), or walk code points (codePointAt) when building the capped prefix.
- **Evidence:** common/src/util/gate-telemetry.ts:143-150 truncateBytes: 'const buffer = Buffer.from(value.slice(0, maxBytes), "utf8")' plus the docblock's 'cutting on a code-point boundary ... no replacement character is introduced'.

## [LOW] security — packages/agent-runtime/src/orchestration/gate-telemetry-sink.ts:41 — Warn-latch key exhaustion via planted symlinks silences all later distinct telemetry warnings (documented, accepted suppression vector)
- **Risk:** warnLatchKey includes the refused symlinkedSegment and the latch is capped at GATE_TELEMETRY_WARN_LATCH_MAX_KEYS (64). A writer who can plant symlinks at 64 distinct paths under projectRoot/.openbuff/telemetry spends every key; each further distinct report — including non-symlink failures like rotation or permission problems whose keys collide with spent ones only if message+code match, or simply new distinct messages beyond the cap — is suppressed for the recorder's lifetime while appends keep failing closed. The failure mode is operator-blindness about why gate telemetry is missing. The code documents this as an accepted trade-off, but no mitigation (rate-limited fallback) exists.
- **Fix:** Once the key cap is reached, fall back to rate-limited (e.g. one per N minutes) unconditional warnings that include a 'further distinct warnings suppressed' marker, so the suppression is itself visible instead of total.
- **Evidence:** packages/agent-runtime/src/orchestration/gate-telemetry-sink.ts:19-41 warnLatchKey + the 'someone able to plant symlinks at many distinct paths ... can spend every key and silence each LATER distinct report' comment; createWarnLatch({maxKeys: GATE_TELEMETRY_WARN_LATCH_MAX_KEYS}) with no overflow behavior.

## [LOW] state-mutation — agents/base2/gate-concurrency.ts:27 — gatePassedFiles short-circuits before selfMutatedPaths: a gate-passed file re-edited mid-turn is never absorbed, so the gate can present PASSED over drifted bytes within the turn
