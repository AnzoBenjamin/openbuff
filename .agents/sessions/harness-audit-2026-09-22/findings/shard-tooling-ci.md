## [HIGH] test-coverage — .github/workflows/ci.yml:203 — CI test job never runs scripts/ tests: `find src` blind spot yields vacuous green job
- **Risk:** The test matrix includes `scripts`, but the run command collects tests with `find src -name '*.test.ts'`. ## [HIGH] security — .github/workflows/nightly-e2e.yml:21 — toJSON(secrets) materializes every repository secret into one step's env and shell pipeline
- **Risk:** `SECRETS_CONTEXT: ${{ toJSON(secrets) }}` puts the complete secrets map (all providers' API keys, the GitHub token source, everything) into a single step's environment and then through `echo | jq`. Any leak in that step (a debug `set -x`, a shell error echoing the pipeline, a compromised script invoked as `bun scripts/generate-ci-env.ts` inside the same step) exposes every secret at once instead of the handful the job needs. It also defeats least-privilege scoping and makes log-masking the only line of defense.
- **Fix:** Delete SECRETS_CONTEXT and name only the env vars the e2e run needs in the step `env:` block, exactly as ci.yml does (explicit `NAME: ${{ secrets.NAME }}` entries consumed via generate-ci-env.ts). Never serialize the whole secrets context into a shell variable.
- **Evidence:** .github/workflows/nightly-e2e.yml:19-26: `- name: Set environment variables` / `env:` / `SECRETS_CONTEXT: ${{ toJSON(secrets) }}` then `echo "$SECRETS_CONTEXT" | jq -r --argjson vars "$VAR_NAMES" '...' >> $GITHUB_ENV`. Contrast .github/workflows/ci.yml:45-66 which lists each secret explicitly by name.

## [MEDIUM] state-mutation — scripts/run-mutation-gate.ts:14 — Mutation-gate wrapper does not forward signals: killing the wrapper orphans the child still running with OPENBUFF_MUTATION_GATE=1
- **Risk:** The wrapper spawns the child and only handles 'exit' and 'error'. If the wrapper receives SIGINT/SIGTERM/SIGHUP (Ctrl-C in a terminal, CI cancellation, hook teardown), the wrapper dies without forwarding the signal, and the child - a full test or agent run with OPENBUFF_MUTATION_GATE=1 in its env - keeps running as an orphan, mutating files or holding ports after the developer believes the run ended. The leaked job also defeats the gate's purpose: its result is never observed, so a mutation-gated run can silently 'pass' by abandonment.
- **Fix:** Register `for (const sig of ['SIGINT','SIGTERM','SIGHUP']) process.on(sig, () => { child.kill(sig) })` (and let the child's 'exit' handler set the wrapper exit code), or use Bun.spawn with signal forwarding. Also consider `child.unref()`-free shutdown so the wrapper exits after the child.
- **Evidence:** scripts/run-mutation-gate.ts:8-18: `const child = spawn(command, args, { stdio: 'inherit', shell: false, env: { ...process.env, OPENBUFF_MUTATION_GATE: '1' } }); child.on('exit', (code) => process.exit(code ?? 1)); child.on('error', ...)`. No process.on('SIG*') handlers anywhere in the file (19 lines total).

## [MEDIUM] performance — scripts/memory-drift-guard.ts:393 — batchLastCommitEpochs is not actually batched: one `git log` spawn per pathspec plus one per topic key, serially
