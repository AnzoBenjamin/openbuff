# Audit Report — Openbuff / audit-polyglot-2026-09 (language-choice synthesis)

Generated 2026-09-26. Synthesized from 5 shard finding files (72 findings). Scope: **which parts of Openbuff (local-first BYOK coding CLI, TypeScript on Bun) would benefit from another language purely from a FEATURE standpoint (Q1), and which brand-new features a language move unlocks (Q2)** — not raw speed. External evidence incorporated: Codex CLI (Rust rewrite: zero-dependency install, Landlock/seccomp sandboxing, no-GC memory); Claude Code (stayed TS/Ink — its loop is I/O-bound); opencode (TS core, TUI rendering moved to a Zig-native OpenTUI core); Aider (embeds native tree-sitter from Python without a host rewrite); Prisma (moved BACK from Rust to TS/WASM — distribution pain, contributor skillset); napi-rs prebuilt per-platform npm packages as the mature Rust-from-Bun/Node path (bun:ffi still experimental); SQLite FTS5 (already bundled via bun:sqlite), usearch (official JS bindings), tantivy (third-party node bindings); ratatui-image (unifies sixel/kitty/iTerm2 protocols); esbuild/swc/turbopack (10–100x toolchain speedups where incremental computation matters).

## Top opportunities (severity-ordered)

1. [HIGH] Search/index — sdk/src/tools/code-search.ts — embed ripgrep crates in-process (Rust/napi-rs); kill per-call process spawn + per-line JSON parse in JS. Feature gained: persistent ranked search. Cost: low-medium; contract-preserving (keep CODEBUFF_RG_PATH override).
2. [HIGH] Indexer store — packages/indexer/src/index-store.ts:1074 — replace whole-artifact JSON rewrites + hand-rolled flock with a transactional native store (sled/redb or SQLite FTS5+vec0). Feature gained: incremental O(delta) persistence, instant warm starts, real BM25 for free. Cost: medium; index-store.test.ts pins lock/CAS semantics — port verbatim.
3. [HIGH] Lexical query tier — packages/indexer/src/query.ts:417 — replace O(files×tokens) substring scorer with tantivy BM25 postings behind the existing queryIndex API. Feature gained: fuzzy/typo-tolerant symbol search, phrase/proximity, chunk-level retrieval at 100k+ files. Cost: low-medium; best test-protected target (query-quality/retrieval-quality/call-navigation suites = golden MRR harness).
4. [HIGH] Embeddings — sdk/src/impl/embeddings.ts — local offline embedding runtime via candle/ort (CUDA/Metal EP) behind the existing EmbedFn. Feature gained: offline/private-repo semantic indexing — a core BYOK/local-first promise blocked today. Cost: medium; must namespace cacheKey ('local:onnx/<model>') to keep vector-space caches isolated.
5. [HIGH] Distribution/build — cli/scripts/build-binary.ts + sdk/scripts/build.ts — Rust core with static-linked tree-sitter/ripgrep, shipped as napi-rs prebuilts / cargo-dist artifact. Feature gained: single-binary install (Codex-rs model), no sibling wasm files, no manifest, no Bun-polyfill chain, no bundler-bug regex surgeries. Cost: medium-high; this is the keystone — several findings below collapse once landed.
6. [HIGH] Parse tier — packages/code-map/src/parse.ts:145 + languages.ts:7 — native tree-sitter crates + rayon parallel walk behind the TS facade. Feature gained: full-repo index without budget truncation; incremental reparse for keystroke-grade live repo maps. Cost: medium; keep .scm queries verbatim, preserve buildTokenCallers contract.
7. [HIGH] Tokenizer — packages/agent-runtime/src/util/token-counter.ts:46 — tiktoken-core (Rust BPE, SIMD) replacing JS gpt-tokenizer. Feature gained: exact per-provider token counts → precise compaction triggers, real-time context meters, no 1.35/1.1 fudge factors. Cost: low (thin, exactly-pinned module).
8. [MEDIUM] Memory — cli/src/services/memory-v2/bun-sqlite-memory-repository.ts:1553 — rusqlite kernel: push fold into SQL (FTS5 + generated columns), add sqlite-vec. Feature gained: shipped semantic memory recall + compact() instead of 'unsupported'. Cost: medium; also fixes the unshippable hardened-open mode (LOW, :318) via a Rust VFS.
9. [MEDIUM] Streaming render — cli/src/utils/markdown-renderer.tsx:1085 + syntax-highlighter.tsx:9 — Rust pulldown-cmark/tree-sitter+syntect addon emitting styled-span data. Feature gained: real syntax highlighting (currently a deliberate stub) + incremental streaming markdown. Cost: medium; prerequisite is the styled-span protocol (see NOT-move section).
10. [MEDIUM] File watching — sdk/src/run.ts + indexer/file-walker.ts:341 — notify (inotify/FSEvents/ReadDirectoryChangesW) watcher component. Feature gained: live external-edit detection, fresh-on-edit reindex, elimination of the 5-minute staleness window. Cost: low-medium; additive SDK event.

## Q2 — Brand-new features unlocked by putting another language on the table

- **Real streaming syntax highlighting** — Rust tree-sitter + syntect native addon; incremental parsing makes per-chunk highlighting affordable (replaces the deliberate stub in cli/src/utils/syntax-highlighter.tsx). *Component: CLI render layer.*
- **Semantic memory recall** — rusqlite FTS5 + sqlite-vec + small local embedding model turns memory-v2 `search()` from `unsupported('semantic-search')` into a shipped feature; also enables `compact()`. *Component: cli memory-v2.*
- **Sixel/kitty/iTerm2 image previews** — Rust `image` crate decode/resize; ratatui-image unifies the three protocols. *Component: cli/src/utils/terminal-images.ts.*
- **Persistent BM25 incremental code index** — tantivy (or FTS5) with notify-driven incremental updates: ranked, fuzzy, phrase, and chunk-level retrieval at 100k+ files, sub-100ms regardless of repo size. *Component: packages/indexer.*
- **Local offline embeddings** — candle/ort with CUDA/Metal execution providers behind the existing EmbedFn; offline/private-repo semantic indexing (BYOK/local-first promise). *Component: sdk/src/impl/embeddings.ts (cacheKey namespaced).*
- **Live workspace watching** — notify/inotify/FSEvents watcher surfacing SDK-level external-edit events; incremental reindex on save instead of the 5-minute staleness window. *Component: sdk/src/run.ts + indexer file-walker.*
- **PTY/control-mode tmux sidecar** — portable-pty or tmux `-C`: structured screen model, real idle detection, process-group supervision, live session monitoring for tmux-cli/basher. *Component: agents/tmux-cli.ts, agents/basher.ts.*
- **Embedded index daemon (`openbuff serve`)** — a resident Rust process owning the index collapses the hand-rolled lock/singleton machinery by construction and serves CLI/SDK/editor from one warm index; static binary means no node_modules for the daemon. *Component: packages/indexer (index-manager.ts IPC client keeps API).*
- **LSP server** — embedded LSP exposing Openbuff code intelligence (symbols, signatures, doc comments — data model already extracted in structure.ts) to any editor over stdio. *Component: code-map + native core.*
- **MCP server** — embedded MCP endpoint so agents/IDEs talk to the CLI over one local socket without npm. *Component: native core / sdk.*
- **Plugin host** — wasmtime-based sandboxed community plugins inside the same single binary (extism-style); adds a trust boundary the current single-user TS process lacks. *Component: native core.*
- **Single-static-binary distribution + delta auto-updates** — cargo-dist-style artifacts; atomic in-place updates become feasible when the artifact is self-contained (today's multi-file tarball makes this fragile). *Component: build/distribution.*
- **OS-level sandboxing** — Codex-rs-style Landlock/seccomp (and macOS equivalents) around tool execution; TS/Bun has no path to kernel sandbox primitives. *Component: tool execution boundary (sdk/run.ts).*
- **Grapheme-correct layout + word-diffs** — unicode-width/SIMD wrap kernel and imara-diff unlock emoji-correct wrapping and intra-line diff emphasis. *Component: cli text-layout.ts, diff-viewer.tsx.*
- **Incremental syntax-aware editing** — native tree-sitter edit/reparse enables structural search, symbol navigation, per-language indentation inference, and syntax-aware diffing wired to the (currently inert) LANGUAGE_CAPABILITY_REGISTRY. *Component: common/src/util/language-capabilities.ts + code-map.*

## What should NOT move

- **The agent loop (packages/agent-runtime).** It is I/O-bound — the Claude Code precedent (stayed TS/Ink) applies directly. Native wins there are limited to the tokenizer and the stream XML parser (both thin, exactly-pinned modules — surgical napi candidates, not a rewrite).
- **OpenTUI/React TUI (cli/src/chat.tsx, app.tsx, components).** 1871-line chat.tsx wires ~40 keyboard/UI handlers; renderMarkdown returns OpenTUI ReactNodes directly (markdown-renderer.tsx:1150). A big-bang rewrite is infeasible (shard-cli explicitly assesses the rewrite boundary as TS). Treat OpenTUI as the one pinned native boundary. Prisma's Rust→TS retreat is the cautionary tale on distribution pain + contributor skillset.
- **Published SDK contract surface (sdk/src/run.ts).** ToolResultOutput shapes, FileMutationResultV1/CommitReceiptV1, ClientToolOverrides dispatch, CodebuffFileSystem adapter (readdirView pairing, hostProcessView gating) are consumed by external hosts — keep as the stable JS boundary with native accelerators behind them.
- **cap.v3 token grammar + content-hash normalization (common/src/util/content-hash.ts).** The widest cross-module contract in the codebase (20+ consumers); HMAC key is process-random, so native components cannot validate tokens without a shared-secret ABI. Freeze as a versioned spec with golden vectors before any native layer touches it; keep minting/verification in TS.
- **Mutation-broker receipts (sdk/src/services/workspace-mutation-broker.ts).** Persisted cross-process durable state ('prepared'/'recovery_required'/final states, schemaVersion 1, zero-padded revision filenames) — a native reimplementation must reproduce the exact schema or version it; only locking/IO internals may move natively.
- **Tool schemas / codegen (common/src/tools/compile-tool-definitions.ts, scripts/generate-tool-definitions.ts).** The three-mirror generated-tools contract is deliberate; a native core's registry must be generated FROM the same Zod schemas, never re-declared.
- **Cross-package caller-edge contract (code-map parse.ts:513).** buildTokenCallers same-language-only rule is pinned by suites in two packages; extract to a shared conformance fixture before any native parse tier lands.

## Recommended incremental adoption path

1. **Never big-bang.** All native work enters as napi-rs prebuilt per-platform `.node` modules behind existing TS interfaces (the mature Rust-from-Bun/Node path; bun:ffi is too experimental). The SDK's npm surface stays byte-compatible in API shape.
2. **Wave 1 — pure-function addons (lowest risk):** tokenizer (tiktoken-core), ANSI strip/suffix-prefix (common/src/util/string.ts), range-read (memmap2+memchr). Each has exact pinned test contracts as the oracle.
3. **Wave 2 — search/index core:** ripgrep crates in-process, then tantivy BM25 tier and the native store (sled/redb or SQLite FTS5+vec0) behind the unchanged queryIndex/IndexManager APIs; port index-store.test.ts lock/CAS semantics verbatim. Keep CODEBUFF_RG_PATH honored.
4. **Wave 3 — parse tier:** native tree-sitter crates + rayon; keep .scm queries verbatim; extract the language-family mapping and buildTokenCallers conformance suite first; WASM pinning tests become obsolete by design.
5. **Wave 4 — CLI feature addons:** highlighting, image protocols, diffs, fuzzy engine — each gated behind the styled-span/line data protocol introduced at the markdown/highlight/layout boundary first (this protocol is the prerequisite for any of it).
6. **Wave 5 — process model:** the embedded daemon/serve, LSP, MCP, plugin host, and cargo-dist single-binary distribution grow on the native side once the core cdylib is stable; TS CLI remains the TUI front end. Contract findings (release.ts dispatch schema, artifact naming, env-var defines) must survive unchanged.

## Cross-cutting findings (span multiple shards)

- **Vendored rg + WASM grammar siblings are a systemic distribution tax** (shard-cli, shard-sdk, shard-tooling): ripgrep vendoring with no checksum verification (fetch-ripgrep.ts), tree-sitter WASM sibling files + sha256 manifest + smoke gates, node_modules patching, legacy Bun 1.0 lane, and three regex surgeries on the SDK bundle all exist because the core is pure JS. A static-linked native core collapses all of them at once.
- **"Native opportunity" is the dominant fix pattern** (all 5 shards): ~2/3 of findings conclude the ceiling is TS/Bun capability, not tuning — corroborating the Q1/Q2 framing.
- **Contracts must be frozen before natives land** (shard-sdk, shard-common, shard-tooling): cap.v3 grammar, broker receipts, tool schemas, readdirView pairing, rg env override, release automation — every shard independently flags a contract that a naive migration would break.
- **Test harnesses protect behavior, not performance** (shard-runtime, shard-cli): strong behavioral suites make native rewrites behavior-safe; no golden throughput/latency corpora exist — add them before/with each wave.
