## Proposed contract

1. **Captured document:** retain exact UTF-8 source bytes or a proven lossless BOM-preserving source string, exact raw hash, separate CRLF-normalized observation/hash, BOM metadata and each terminator's original spelling. Do not repurpose `getContentHash` or infer raw bytes from numbered/decorated text. `TextDecoder({fatal:true, ignoreBOM:true})` can preserve U+FEFF; explicitly separate the leading BOM from observation coordinates. A later U+FEFF remains content. Invalid UTF-8 and supported-policy refusals issue no authority; string adapters can certify only the bytes their own view actually supplies.
2. **Coordinates and lines:** conversions explicitly name observation UTF-16, UTF-8 payload bytes and raw bytes (including the three BOM bytes). For BOM + `a😀b`, observation offsets 1 and 3 map to raw byte offsets 4 and 8; offset 2 splits the surrogate pair and refuses. CRLF's normalized LF maps to its two raw bytes; no splice boundary may split a scalar or terminator. Preserve `line-coordinates.ts` visible versus capability ceilings: empty file has zero visible lines/one capability entry; `a\n` has one visible line plus a final empty capability entry; `a` has one line with no terminator. Coordinate tables are bounded to captured text, never built for an unretained 24 MiB line.
3. **Localized splice:** translate the accepted target in the captured observation onto the raw source span and assemble exact original prefix + replacement + exact original suffix. BOM and outside-target EOL/bytes remain identical. Preserve existing `replace-range.ts` local insertion-EOL/ending-terminator policy; state separately whether the final-empty entry is targeted. Explicit whole-file replacement may set its supplied bytes/final newline. A whole-file normalization followed by a best-effort EOL reconstruction cannot certify the unrelated-byte invariant.
4. **Mutation:** exact preimage/hash and mode are captured before preparation and used unchanged for forward CAS, delete/move and compensation. `readOptionalText` currently strips a Buffer BOM; fix this capture, not the broker comparison. Keep current B03 evidence/status populations. Successful ordinary update/move and rollback restoration preserve permission bits (`mode & 0o777`); byte+mode assertions use actual Node/broker operations, not string-only mock files.
5. **Authority:** whole authority binds all actually observed raw bytes, including BOM and final terminator. Scoped authority binds the exact observed raw slice plus its boundary rules and project/path/run; any unique reanchor proves the same raw slice at its new location. Unrelated outside-scope drift must not be rejected solely by replacing scoped basis with a whole hash. Inside-scope EOL/BOM-only drift refuses even when normalized hash matches. Complete requested content, known EOF/total, coherent observation and raw basis are distinct facts. A partial window, missing basis, display text or adapter claim cannot promote to whole authority; reminting must carry authenticated basis rather than recompute it from rendered content.

## Allocation implementation, accounting and cancellation

`node-filesystem.ts:162–199` retains subarrays for every line and concatenates a whole line before checking the budget. Simply capping the returned buffer, using `subarray(0, budget)`, or replacing that concat with a growing string still fails: slices retain their complete backing buffer and strings/decoder state also count.

Recommended minimal algorithm: one owned budget-sized output backing buffer B and one explicitly sized input chunk C (proposed 64 KiB). Copy only admitted selected bytes into the output buffer; count skipped LF bytes without retaining text. Track pending selected-line bytes within the same B allocation. If a line exceeds the remaining budget, rewind its pending bytes, mark coverage incomplete and discard the rest of that line; never concatenate it. Return a view of the owned output allocation, avoiding a second B-sized final concat. Avoid Buffer pool slab ambiguity with explicit owned allocation. B is finite/validated, and zero-budget behavior is explicit rather than silently coerced.

The leader selected **bounded scan to EOF** on 2026-11-07. Hash full observed bytes and the requested raw span incrementally while counting skipped LF bytes; retain no extra text. Known-total compatibility stays intact. A fully scanned snapshot may have complete EOF/total/hash metadata while its returned window remains `complete:false`; that truncated output grants neither whole authority nor a complete scoped-line grant. Scan-to-EOF does not promise an immutable file snapshot against arbitrary external writers: bind the bytes actually observed and refuse detected drift; stronger coherence claims need an actual adapter primitive and oracle. A provider unable to reach EOF or furnish the required verified basis reports incomplete/unknown metadata and refuses authority, rather than supplying guessed totals.

Measure **peak retained allocation** at actual allocation/read/copy/return seams: deduplicate live ArrayBuffer identities, count full backing capacities (including active/prefetched chunks and returned views), and account for decoder strings/pending storage if present. With descriptor reads there is one C input buffer; with a stream, declare and measure its real high-water/prefetch envelope, not an assumed single chunk. Require `peak <= B + C + declared fixed overhead`; fixed overhead must be numeric, selected before the run, independent of file/line length, and include library-owned buffers. Report output bytes, scanned bytes, largest allocation and peak separately. RSS/process maximum is measured in a separate child process and reported separately; it is neither the retained-allocation proof nor inferred from it.

Pass an approved signal through SDK reads to the actual adapter. Pre-aborted requests open nothing; abort while retaining, skipping or scanning totals destroys/closes the stream/descriptor, removes listeners, settles the promise and emits no later grant. Verify the close event/finally path before resolving abort. The existing bounded byte `readRange` already closes its descriptor in finally. Whole reads also need a bounded primitive: `read-files.ts:428` does unbounded `readFile` after stat, so a growth race can allocate the entire grown file before the later cap. A post-read rejection is not allocation enforcement.
