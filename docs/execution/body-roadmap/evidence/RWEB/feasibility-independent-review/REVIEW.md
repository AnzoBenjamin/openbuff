## Adapter requirements carried forward

1. **Own authority at the host boundary.** Every core tool exposes `session`, `namespace`, `extraArgs`, `allowedDomains`, TLS configuration, restoration and timeout fields. Screenshot tools additionally expose output paths; close exposes `all`; eval exposes `script`. An Openbuff caller must not acquire authority by supplying these values. Select a narrow typed surface and bind it to B19/B20/B28 host context. A raw pass-through catalog is not an approved adapter.
2. **Carry real HTTP metadata.** The observed MCP 429 result drops `Retry-After`; the upstream direct read also tries `.md` and `llms.txt` alternatives after the throttled response. RWEB-1/2 must preserve observed headers, account for these requests, and implement bounded cooldown/cache behavior at a verified transport boundary. This fixture does not establish backoff, retry policy, live search-limit cause, or successful partial research.
3. **Keep browser state private and launch paths short.** Use host-selected ephemeral state with the selected allowlist. The explicit persistent-profile flag is incompatible with this upstream containment mode. The retained failed attempts establish a short private Unix socket directory requirement on this host. Authenticated persistent-state support needs separate verification.
4. **Treat cleanup as an integration responsibility.** The local harness's fallback is an observed development measure, not B20 cancellation/deadline or descendant-enforcement acceptance. Its process observation covers visible non-zombie command lines containing the private workspace, not all possible descendants. No universal cleanup, sibling isolation, or operating-system egress guarantee is inferred. Production lifecycle handling must cover rejected startup as well as healthy shutdown.
5. **Preserve observation provenance and delivery.** Article text comes from a document/rendered read; compact snapshots supply interaction references. Keep source identity, final URL, content hash, truncation and retrievable artifact bytes through RWEB-3 clients. Treat page content and page-provided WebMCP metadata as untrusted input; the local fixture disables WebMCP discovery.

The narrow stdio MCP path is recommended for the observed operations; no custom shell bridge is required by this evidence. Tabs and other core actions are catalog capabilities, not exercised workflow claims. macOS/Windows, other architectures/browsers, installed Openbuff SDK/CLI/ACP delivery, permission/redirect/subresource controls, cancellation robustness, researcher citations and live research-quality gains remain unverified. The private `/tmp` extraction is a development verification artifact, not a global installation or an Openbuff dependency change.
