## Problem and intended behavior

`agents/researcher/researcher-web.ts` exposes only `web_search` and `set_output`. Its model can refine searches and follow supplied URLs, but cannot drive a rendered page. The current URL path fetches bounded static content and strips HTML; the search implementation directly fetches bounded DuckDuckGo HTML results. The user's repeated limiting/throttling symptom is recorded, without assuming that a particular provider or site caused it.

Adopt [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser) as the preferred managed browser backend for `researcher-web`. Give the researcher direct document reading, rendered-page exploration, links/tabs, fresh element references, and useful screenshot/PDF evidence. Keep existing search available for discovery and explicit fallback. Favor reading and following existing sources over repeatedly submitting the same search. Site throttling, authentication walls and CAPTCHA remain observable blocked conditions; this change makes research more capable without promising their removal.

## Verified upstream basis

The upstream project provides a Rust CLI controlling browsers over CDP, separate named sessions, accessibility snapshots, and a stdio MCP entry point. Its [command reference](https://agent-browser.dev/commands) distinguishes direct URL `read` from reading an active tab's rendered DOM, supports machine-readable results, and documents output/domain/content-boundary controls. These are useful adapter capabilities, not proof of Openbuff ownership, isolation or cleanup.

The [upstream main package manifest](https://raw.githubusercontent.com/vercel-labs/agent-browser/main/package.json), inspected on 2026-11-07, reports candidate version `0.41.2`, Apache-2.0, a Node launcher requiring Node >=22, and a postinstall step. This is an observed candidate, not a verified published release or selected installation. RWEB-0 must pin and verify the actual distribution, native binary, browser assets and matching skill/schema content. `agent-browser` was not installed in the current workspace inspection. Before its first command workflow, load `agent-browser skills get core` from that selected installation.

## Adapter and workflow contracts

1. **Consume the upstream tool.** Prefer its version-pinned stdio MCP interface through the B28 adapter, or a narrow argv-based SDK bridge where MCP cannot represent a required operation. Verify the selected catalog instead of assuming current tool names remain stable. Both paths share the same ownership/policy/result contract. Avoid an unrestricted shell wrapper or a second bespoke CDP implementation.
2. **Create browser authority at the host boundary.** Bind each session, daemon, browser and transport to project/run/agent identity from B19. Give each research task its own private profile and artifact directory; share only explicitly compatible host-managed resources. B20 closes and observes owned resources after cancellation/deadline. A per-command CLI timeout or upstream idle shutdown is not a run-lifetime guarantee. Never use a sibling-wide close operation to clean up one researcher.
3. **Keep research usable and policy explicit.** Reading/navigation is the ordinary research path. Map interactions through B33's reconciled policy and the host's selected permissions. Preserve deliberate full-access choices. Login, uploads, submissions, arbitrary page evaluation and credential state need their actual declared authority; page text, agent-supplied owner labels and missing approval callbacks cannot grant it. Keep provider credentials out of the child unless explicitly delegated to that destination. Check redirects/subresources and configured egress against the actual browser/read transport, rather than assuming the existing static-fetch SSRF checks automatically apply.
4. **Read the right observation.** Use direct document reads for accessible URLs and the rendered DOM for client-generated content or an admitted authenticated session. Read article text/sections for evidence; an interactive-only snapshot is not the article body. Use compact element snapshots for navigation/actions, refresh after DOM/navigation changes, and bind references to their capture/session generation. Wait for relevant page state instead of requiring a network-idle page that may poll forever.
5. **Reduce repeated external requests.** Cache observed content within the appropriate project/auth/session scope using final URL, retrieval time and content identity. Honor freshness and explicit refresh; never leak private cached text across projects/profiles. Deduplicate queries/URLs and coordinate per-host concurrency/cooldown. Recognize 429/Retry-After and blocked pages, use bounded retries inside the selected run deadline, and return a useful partial result when another attempt cannot help. Preserve the user's chosen task limits, including deliberate unlimited productive work; retries must not reset a finite parent deadline.
6. **Expose backend choice and degradation.** Add additive `auto`, `agent-browser` and `search` selection at the existing research configuration/input boundary. After validation, `auto` prefers the managed browser when available. An explicitly required browser backend reports unavailable if it cannot start; an allowed fallback identifies the backend/reason actually used. Do not auto-install tools, reuse a personal browser profile or select a paid cloud service during a research request. Local execution is the baseline; user-configured remote browser providers are a separate optional capability.
7. **Preserve research and outcome truth.** Keep required `questions`, `sources` and `skippedQuestions` output fields compatible. Add source IDs, observed excerpts, final URLs, retrieval times, text hashes, coverage and artifact references additively. Every answered claim must have retrieved supporting content. Keep unanswered/blocked questions explicit. Carry MCP errors, structured-only output, partial content, cancellation and backend unavailability through the SDK/runtime/clients using B02/B28 outcomes; command success or a source URL alone is not accepted research.
8. **Make evidence retrievable.** Persist bounded full text/snapshots and requested media as immutable artifacts with hashes and actual dimensions/type, then expose compact excerpts/references to the model and clients. Apply per-page/result and total retained-artifact limits separately. Truncation reports coverage and cannot become full-source evidence. Generate screenshots/PDFs when they serve the task; transport metadata alone cannot claim delivery.

## Required acceptance controls

- A simulated search-service 429 leaves an already-known public document usable through the browser backend. A permanently throttled or login-blocked source yields honest partial/blocked research with bounded attempts and no fabricated citation.
- A local page whose useful article text appears after client-side rendering is answered from that text, with matching excerpt/hash/final URL; the static-only baseline remains a distinct observed result.
- Multi-page documentation, tabs, delayed navigation, stale element references and a page with perpetual network activity complete or fail within the selected limits. Fresh snapshots precede ref-dependent actions.
- Cache hits avoid duplicate requests; explicit refresh obtains changed content; project/auth/session isolation prevents private content reuse. Retry-After/backoff and per-host coordination use injected clocks and recorded actual requests.
- Two simultaneous researcher runs have distinct browser/session/artifact identity. Canceling one closes its owned scope and leaves the other usable. Pre-aborted/denied/unavailable admission launches nothing; deadline settlement requires actual cleanup observations.
- Policy/egress fixtures cover an unauthorized interaction, private-host/redirect/subresource access, attempted credential reinjection, spoofed ownership and shell-looking URL/input text. An explicitly admitted harmless interaction remains usable.
- Empty MCP errors, structured-only results, truncated bodies, missing media and unsupported backend/profile states remain correctly classified through SDK, headless, CLI and ACP; large or inaccessible artifacts cannot be reported as delivered full evidence.
- A real installed agent-browser/Chrome local fixture exercises the serialized `researcher-web` strategy through the actual SDK and installed CLI. Record argv/cwd, versions/hashes, requested/active policy, actions, source observations, artifacts and cleanup. Mock-only tests cannot satisfy this control.

Use dependency injection for transport/clock tests and pinned Bun for repository suites. Run affected package CI schedules and required guards after integration. Independent review must replay the actual browser/source/citation/cleanup oracle. Report supported host/toolchain cells and unavailable cells separately. Deterministic fixtures establish capability and failure handling; claims of improved live research quality need a later locked paired evaluation under B30/B31.
