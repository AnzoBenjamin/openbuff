# SDK Package Knowledge

## Memory recall and local embeddings

- `sdk/src/services/memory-v2/coordinator.ts` retrieves prior project evidence across task boundaries; the active task ID remains on lifecycle events and turn context rather than restricting startup retrieval to a new task with no observations.
- Complete native `read_files` results establish file freshness only when their schema, metadata, edit anchor and whole-file `cap.v4` raw basis agree. Evidence and verification use the same actual raw file digest. Confirmed mutations use their observed after-hash, including the destination for moves; discovery counts do not establish file freshness.
- `sdk/src/provider-config.ts` merges indexing settings only when a declaring file or fragment explicitly supplies them. Defaults from unrelated fragments must not disable configured semantic indexing.
- `sdk/src/impl/embeddings.ts` uses serial batches of at most eight inputs for loopback endpoints and exposes that preference through `EmbedFn.maxBatchSize`. Cache identity includes the resolved provider, endpoint and model, excluding credentials. The [local mode guide](../docs/local-mode.md) documents Ollama configuration, vector checkpoints and the index warming script.

## Memory V2 terminal events and provider diagnostics

- `sdk/src/services/memory-v2/coordinator.ts` assigns startup `task.transitioned` drafts source index 1 and completed/failed/cancelled transition drafts source index 2. These events share task identity but must have distinct append-only event IDs. Repeated terminal delivery retains its deterministic identity for idempotent replay.
- Coordinator append warnings include the storage rejection message alongside outcome, code and attempt, so lifecycle event conflicts can be traced from logs.
- The provider stream/retry diagnostics in `sdk/src/impl/llm.ts` call `getErrorObject` with `includeRequestBody: false`. This avoids serializing the potentially large typed request body during routine error reporting while retaining error classification and metadata.

## Command defaults and attached job lifetime

- `sdk/src/tools/run-terminal-command.ts` resolves timeouts through `resolveTerminalTimeout`: an omitted SYNC timeout is a 120 s execution-time default armed at dispatch (approval waits excluded), explicit values keep their documented meaning, and a trusted `timeoutPolicy` can cap or forbid `-1`. SYNC stdin is closed (`ignore-pipe-pipe`). A 30 s silence adds `idleOutputHint`/`idleOutputMs` without stopping the command, and cancellation keeps partial output and the spool artifact.
- `sdk/src/tools/attached-job-lifetime.ts` owns attached BACKGROUND jobs: it unrefs their handles, runs the cooperative `owner-shutdown` scope stop on `beforeExit` and SIGINT/SIGTERM/SIGHUP, exits with 128 + signal only when no other listener owns the signal, and SIGTERM→SIGKILLs groups synchronously on `exit`. Hooks exist only while an attached job is live. Transferred jobs are not registered. Real-process coverage: `sdk/src/__tests__/attached-job-exit.test.ts`, `terminal-sync-defaults.test.ts`.

## Routine execution and CI controls

- Balanced approval permits routine Git reads and project scripts. Client-origin MCP startup retains separate process approval even when the interpreter is a known routine executable; trusted project/user startup registration and exact action binding stay authoritative.
- Containment and sensitive-read fixtures select `sandbox.mode: "project"` explicitly. A host-profile control must choose a profile distinct from the captured default, and direct terminal fixtures inherit that captured profile.
- `sdk/src/host-execution.ts` retains the run's selected portable execution profile for repository bootstrap observations. An installed native backend uses the portable default for bootstrap; a missing required native installation is reported at target preparation before policy approval or child dispatch.
- Launch observers include native preparation, transport and target-entry methods alongside portable spawn/failure/cleanup methods. Their presence does not grant native authority: the methods validate the captured native dispatch and bound observer receiver.
- Full SDK CI discovery includes every non-integration `.test.ts` and `.test.tsx` file under `bun test --isolate`. Local server/IPC scenarios require a host that permits those operations. The current repaired local schedule passes 5,753 tests across 194 files.
- The real-child deadline-disarm test gives `printf` a five-second finite lifetime for loaded-runner startup, verifies exit code zero with no termination signal, then waits past the captured native deadline. Its ten-second test budget preserves the no-late-kill assertion; the separate 100 ms backstop case still verifies prompt expiry.
- Real sidecar cleanup tests wait for Linux process-exit evidence as well as fixture markers before asserting that the leader is gone while its TERM-resistant writer remains. The fixture deliberately delays exit after announcing it, so marker creation cannot substitute for OS observation. Liveness reads treat ENOENT and ESRCH as disappearance; permission and malformed-observation failures still propagate.

## Filesystem sandbox configuration

- Agent runs default to unrestricted filesystem and terminal path access. `sandbox.mode: "project"` opts into tool-level containment; absolute `sandbox.allowPaths` entries grant additional writable directories through the captured configuration trust gate. This policy does not provide OS process or network isolation.
- `sdk/src/host-config.ts` captures an immutable policy per run. `sdk/src/run.ts` binds it to asynchronous execution and filesystem adapters, and the mutation broker uses the same policy for external edits. Supervised children inherit the captured policy independently of concurrent runs.
- `sdk/src/__tests__/filesystem-sandbox.test.ts` exercises external reads, writes, searches, terminal working directories, configured restrictions, and concurrent policy isolation.

## Polyglot first-wave contracts

- SDK reads preserve exact UTF-8 BOM and terminator bytes separately from normalized observation text. Bounded Node readers retain a result buffer plus one fixed chunk, and localized edits verify the captured raw basis before committing. ACP/MCP outbound text redacts both legacy `cap.v3` and current `cap.v4` tokens.
- SDK results, ACP events and journals retain separate run, task and action outcomes. Mutation dispatch and review bundles use observed forward receipts; compensation failure preserves uncertainty without certifying foreign or unapplied bytes.
- `sdk/src/run.ts` keeps startup dependencies abortable. Once runtime cancellation is ready, it waits for tool, callback and runtime cleanup before returning final history and action outcomes. User lookup is raced against cancellation too.
- Terminal branch-control input tables live in `sdk/src/__tests__/fixtures/`. Normal execution fixtures retain captures in memory; receipt files require the explicit evidence-directory variables documented in the [testing guide](../docs/testing.md).
- The cooperative mutation broker refuses ambiguous stale ownership and retains recovery-needed records. Native crash reclamation and descendant cleanup remain pending. Terminal approvals bind the captured command, environment, path and one-shot identity.
- Provider configuration preserves the selected route and shared retry/error metadata. Evaluator workers use an explicitly declared environment-isolation tier, with recorded failures and artifact coverage retained separately from task acceptance.
- See the [body checkpoint](../docs/execution/body-roadmap/STATE.md) for source/build verification and the pending agent-browser researcher prerequisites.

## Dashboard capture and request ownership

- `sdk/src/dash/server.ts` binds timeline requests to the selected-run generation and receipt/gate requests to their panel generations. Late responses and errors cannot overwrite newer selections. Refresh retains captured data while exposing loading/error feedback; local Find and expandable event/field details inspect that retained snapshot.
- `sdk/src/dash/provider.ts` returns the latest bounded event window using `DASH_MAX_EVENTS`, currently 2000. Event rows retain `payloadSummary`, bounded `payloadDetail`, `payloadTruncated` and source time when available. Payload projection limits nodes/depth/characters and avoids invoking object accessors; bounded detail is not a complete journal payload guarantee.
- Providers can report source availability through optional `getSourceStatus`. `sdk/src/dash/export.ts` stores source status and `capturedAt` in static snapshots. Offline exports identify capture time and disable live refresh controls; timeline labels distinguish the captured window from older source events.
- `sdk/scripts/build.ts` can reuse a grammar from an earlier local CLI build only after the shared resolver verifies the immutable SHA-256 pin. The build retains Node ESM/CJS required-export checks; artifact reuse does not relax integrity or consumer-export validation.
- [CLI overhaul acceptance](../docs/design/cli-overhaul/README.md) retains the dashboard and supporting UI validation scope. Automated keyboard/geometry checks do not establish screen-reader or human usability acceptance.

- CI regression coverage: the failed-cleanup test in `sdk/src/__tests__/3d-assets.test.ts` cancels after writing attempt metadata, before launching Blender, and verifies no guarded commit occurred. It exercises retained artifacts without requiring Blender on CI runners. Symbol batch tests in `packages/agent-runtime/src/__tests__/read-files-edit-state.test.ts` cover both complete reads within the current budget and omitted symbols above it.

- Output recovery: SYNC terminal overflow is streamed to a full JSON artifact through `sdk/src/tools/terminal-output-spool.ts`; failures return `logPersisted: false` without a path. Directory listings accept `offset` and `limit`, return `nextOffset` when more visible entries remain, and apply read policy before pagination. Background output reads now allow 1,000,000 bytes. Blender operations use an attempt-owned JSON file; `sdk/src/tools/3d-artifact-retention.ts` retains recent receipts across calls with per-project adapter state, a rotating bounded stat window, and scans across operation directories.

## Command approvals

- Command approvals resolve once per host run: an explicit SDK `approvalMode` option overrides the captured config; otherwise `openbuff.json` supplies the mode (default `balanced`). `run.ts` passes this resolved value through to all tool dispatch. Editing config while a command awaits approval cannot change the active run's policy.

## Request token overhead

- `OpenbuffClientOptions.projectContextMode` selects eager `'symbols'` scoring (the SDK default) or `'paths'` startup context. `run.ts` forwards the mode to initial and continued session preparation in `run-state.ts`; path mode refreshes the tree and knowledge files without reading source for token scores. Virtual project files and explicit knowledge overrides remain authoritative, and retrieval tools can still parse symbols on demand.
- `countToolSurfaceTokensForCalibration` exposes the SDK request's tool-surface token projection, honoring the provider's `includeTools` decision. The runtime retains its own tool-definition projection without importing SDK internals.
